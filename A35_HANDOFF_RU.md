## Изменения

- Завершённая беседа сотрудника имеет три компактные вкладки: ИИ-разбор, беседа/этапы, отзыв наставника. Нет длинной страницы со всеми разделами и перекрывающей sticky-панели. При наличии опубликованного отзыва исходно открывается вкладка с оценками. Вкладки используют ARIA/клавиатуру и запоминают позиции; текущая тренировка/компания/история не перестраивались.
- ИИ-разбор показывает статус и до трёх строк сохранённого резюме; полный текст открывается по кнопке в полноэкранном просмотрщике. Ошибка последнего refresh не скрывает прежний сохранённый результат и не считается новым успешным анализом. Повторная генерация — вторичное ручное действие с подтверждением возможного платного вызова. Страница и скачивание ничего не генерируют автоматически.
- Транскрипт, подробные три фазы с доказательствами, исходный справочник и опубликованный отзыв открываются в том же общем просмотрщике, что у наставника. Собственная прокрутка, закрытие/Escape, возврат на прежнюю вкладку/позицию, переход по цитате к реплике. Явно выбранная аудитория: learner использует только s.analysis; приватный s.mentor_analysis не подставляется даже при наличии лишнего поля в клиентском объекте.
- В отзыве сначала итог учебной цели и структурные оценки трёх фаз, фактический исход и соответствие услугам, автор/дата. Рукописный текст — ниже, в отдельном документе по кнопке. Старые опубликованные наблюдения сохранены и читаются в полном документе/экспорте. Ничего не редактируется и не публикуется задним числом.
- Метка прочтения сохраняет прежнюю семантику: вход на страницу/вкладку оценок, просмотр ИИ или скачивание не отмечают отзыв прочитанным. IntersectionObserver в прокручиваемом документе отправляет прежнюю read receipt только при появлении опубликованного текста на экране; закрытие/смена документа отключают наблюдение. Оригинальные отзыв/оценки не изменяются.
- Для learner-документа текста отзыва используются поверхности/цвета темы, без светлой заливки в тёмном режиме. A34 для истории сохранён.

## Почему не было рекомендуемого шага

Read-only сверка RU-попытки из скриншота (`86817775a47c4e389062e2d2a16191eb`) подтвердила старый ready result без поля recommendation, с failed refresh. Исходный разбор не переписывался и новая рекомендация модели не выдумывалась.

Теперь новый model advice отображается как сохранённый предварительный совет; рядом есть рабочее доступное действие. Для старого результата явно сказано, что отдельная рекомендация не сохранена. Действие определяется состоянием workflow: опубликован отзыв → открыть отзыв; submitted → ожидать проверку; not_submitted → явно отправить наставнику, даже без успешного ИИ. Сохранённые repeat/try_another_scenario показывают прежние ручные переходы, не запускают новую попытку сами. Рекомендация ИИ и состояние публикации не смешиваются.

## Ручная приёмка и установка

Исходники0.14.0-learner-review-compact. По сохранённому поручению владельца после проверки выполняется штатная активация с SQLite backup API и сверкой защищённых таблиц. Точный установленный код/PID/revision и результат сверки фиксируются в следующем дополнении. До активации новый backend export не выдавать за загруженный старым процессом.

1. Открыть свою завершённую беседу: три вкладки, без длинной страницы/перекрытия нижней панелью.
2. Во вкладке ИИ проверить короткий summary, прежний failed-refresh статус и полный документ; скачивать только при желании. Новый платный refresh для этого не нужен.
3. В беседе/этапах открыть три фазы, перейти к реплике, закрыть и проверить возврат; исторический справочник остаётся справочником этой попытки.
4. В отзыве увидеть сначала итог/оценки наставника. По кнопке открыть его текст ниже оценок, прочитать или скачать PDF/TXT. Проверить badge прочтения.
5. Для старой RU-попытки next step должен открывать уже опубликованный отзыв, не требуя генерации. Для отправленной без отзыва — ожидание, для личной — явная отправка. Проверить обе темы.
