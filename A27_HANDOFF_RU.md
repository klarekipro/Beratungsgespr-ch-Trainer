## Защищённая диагностика следующего отказа

Новый локальный `runtime/dashboard/review_failures/<capture_id>.json` содержит замороженные session/context, фактический payload, инструкции, wire-схему, полученный wire-результат (либо текст модели при ошибке JSON), безопасную диагностику и SHA256 обработчика. Записывается только при отказе. HTTP-заголовки, cookie и переменные окружения не собираются; известный API-ключ удаляется из строк. Каталог0700, файлы0600, вне Git и HTTP. Журнал получает только случайный capture_id/status и прежние безопасные поля, сотруднику диагностика не возвращается.

Пределы: максимум5 файлов по512КиБ; при записи удаляются старейшие/старше7дней. Отдельного фонового удаления нет. Текст модели удерживается до128КиБ; слишком большой bundle не сохраняется (status=oversize). При отсутствии модельного ответа (HTTP/timeout/невалидная оболочка) status=no_response, сохраняются безопасные причины, а не HTTP-тело. Ошибка записи не отменяет сохранение прежнего результата.

Офлайн-повтор, без провайдера/базы:
`.venv/bin/python scripts/replay_review_failure.py runtime/dashboard/review_failures/<capture_id>.json`

Он выполняет ту же привязку и проверку, печатает только безопасный итог/путь/причину. Проверяет права/размер файла и hash обработчика; при смене обработчика нужен соответствующий checkout. Приватный bundle не копировать в Git, handoff или общий журнал.
