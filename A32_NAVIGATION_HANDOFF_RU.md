## Активация и ручная приёмка

Рабочая БД не менялась,8100 не перезапускался: запрет владельца соблюдён. Frontend-файлы обслуживаются с диска, поэтому после обновления страницы вкладки доступны; **новый endpoint PDF/TXT приватного разбора ещё не загружен старым процессом8100**. Для полной активации нужен отдельный разрешённый штатный перезапуск. Startup выполняет служебную инициализацию SQLite, поэтому без разрешения владельца его не выполняли. Не объявлять backend0.13.8 установленным или приватный PDF готовым на старом8100. Старый runtime frontend fingerprint также не является новым fingerprint.

После разрешённой активации, с согласованной backup API перед операцией, штатный запуск — `.venv/bin/python scripts/local_installation.py start --no-browser`; затем отдельно подтвердить фактические версию/процесс/базу. Не переносить данные со стенда8101 и не запускать seed/импорт ради приёмки.

Порядок ручной проверки:

1. Наставник открывает уже отправленную попытку. Проверяет короткий статус и локализованные три вкладки. Новый ИИ-разбор для этого не нужен.
2. Вводит отзыв и меняет оценки, не сохраняет. Переключает все вкладки и возвращается — значения и позиция должны сохраниться. Те же проверки с клавиатуры.
3. Открывает каждый документ. Проверяет собственную прокрутку, переход от цитаты к реплике, закрытие/Escape и возврат в прежнюю вкладку; из транскрипта — исторический снимок и обратно.
4. Скачивает PDF/TXT транскрипта и приватного разбора. Сохранённый анализ/счётчик генерации не должны меняться. Старый backend до активации не поддерживает последний маршрут.
5. Сохраняет черновик; у сотрудника он и приватный разбор не видны. Повторно открывает форму и проверяет восстановление полей. Прежние наблюдения должны остаться в расширенном разделе.
6. Только своим явным действием публикует отзыв; у сотрудника проверяет текст/оценки. Приватный ИИ-разбор остаётся недоступным. Сертификат не выдаётся автоматически.
7. Проверяет разрешённый список других попыток, расширенную диагностику и отдельность сертификатов. Повтор ИИ не нужен для UX-приёмки; отмена подтверждения не должна посылать запрос.
