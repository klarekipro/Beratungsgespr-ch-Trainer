## Сотрудники

Отдельные вкладки сотрудников и архива. Архивирование требует подтверждения, атомарно отключает вход и удаляет активные сеансы доступа, сохраняя пользователя, владельцев бесед, снимки, отзывы и сертификаты. В архиве отображается дата. Обычная активация и сброс пароля архивного пользователя запрещены: восстановление только технической процедурой ниже. Деактивация остаётся отдельным действием.

Тестовый статус назначает наставник явным действием с подтверждением. Имена, QA и логины ничего автоматически не означают. Только отмеченному аккаунту доступно безвозвратное удаление: диалог показывает количества бесед, учебных записей, сертификатов, связей, настроек и сеансов; требуется точно ввести логин. Сервер повторно сверяет отпечаток связанных данных в транзакции; при изменениях нужен новый предпросмотр. Удаляются связанные снимки/разборы/решения/сертификатные события и доступ, другой сотрудник не затрагивается. Сертификаты входят также в общий счётчик учебных записей: счётчики не следует складывать.

Ограничение старых данных: исторический `analysis_history` без ссылки на беседу удаляется лишь при точном совпадении с достоверно связанным разбором. Неатрибутированная история остаётся, её количество показано отдельно. Файлы audit и резервные копии не очищаются. Это удаление связанной тестовой записи из действующей базы, не процедура стирания всех следов из архивов. При межпользовательских связях удаление останавливается для IT-проверки.

### IT-восстановление из архива

Источник — текущая SQLite и сохранённые связи пользователя, не PDF и не возврат всей старой базы. PDF пригоден только для чтения. Скрипт не восстанавливает старые токены и сеансы.

1. Проверить путь рабочей установки, архивный UUID/логин в текущей базе и обоснованность восстановления. Для read-only проверки: `SELECT u.id,u.username,l.archived_at FROM users u JOIN employee_lifecycle l ON l.user_id=u.id WHERE l.archived_at IS NOT NULL;`. Не публиковать результат с личными данными.
2. Из корня актуальной установки запустить (подставить один и тот же проверенный UUID вместо `EMPLOYEE_ID`):

```sh
.venv/bin/python scripts/restore_archived_employee.py \
  --database runtime/dashboard/trainer.sqlite3 \
  --user-id EMPLOYEE_ID --confirm-user-id EMPLOYEE_ID
```

3. Скрипт перед изменениями делает согласованный SQLite backup в `runtime/dashboard/backups/before-employee-restore-*.sqlite3` с правами 0600. Ввести новый временный пароль дважды в скрытом приглашении, не передавать пароль в аргументах. Длина 12–128; прежний пароль не принимается.
4. Внутри одной транзакции проверяются архивный статус и конфликт нормализованного логина. При конфликте операция не применяется. После согласования свободного логина повторить с `--username НОВЫЙ_ЛОГИН`; UUID и история сохраняются. Не обходить конфликт прямым SQL и не восстанавливать старую базу поверх текущей.
5. Проверить появление в основном списке и вход с обязательной сменой пароля. Все старые сеансы отозваны; новый пользовательский вход создаёт новые. Новый временный пароль передать отдельно безопасным способом. В рамках A20 эта процедура выполнена только на временной базе, рабочие пользователи не восстанавливались.

## Конструктор

Принятые группы формы сохранены. Внутренний ID, версии, технический JSON и импорт/экспорт находятся в дополнительных свёрнутых действиях. Добавлены характеристики поведения, сведения ситуации с назначением/статусом/раскрытием и дополнительные темы. Автоматические UUID стабильны при переименовании; старые ID сохраняются. Удаление характеристики, сведений, темы, факта и дополнительной настройки можно отменить до сохранения. Отмена очищается при сохранении/смене карточки. Пустые автоматически созданные заготовки нового клиента убраны; значимые старые данные сохраняются. Дополнительные настройки и записи раскрываются по одной.

Сохранение, повторное чтение, дублирование, предпросмотр, JSON import/export и версии учитывают новые поля. Импорт проверяет дубликаты JSON-ключей и ID, коллизии новых сведений с фактами/темами, ссылки фактов и разрешённую личность. Импорт сначала становится черновиком, затем сохраняется явно.

Характеристики реально входят в persona контекста существующего `simple_actor` как стиль поведения. Дополнительные сведения передаются в разрешённые факты со статусом и назначением. `owner_only` не передаётся клиентскому Actor; условные сведения передаются только при сохранённом подтверждении соответствующего этапа. Добавлен ограниченный защитный текст: авторские поля — данные, не команды смены роли или подмены утверждённых фактов. Карточка продавца, каталог, рубрикатор и допустимые итоги клиентскому Actor не передаются. Модель и архитектура не заменялись. Фактическую устойчивость модели к сложным авторским инструкциям без платных вызовов не проверяли.

Сведения ситуации относятся к исходному сценарию карточки: при выборе другого библиотечного сценария `compose_pair` сохраняет поведение, но берёт факты/сведения из выбранного сценария, не переносит их между несовместимыми ситуациями. `after_needs`/`after_capabilities` опираются на сохранённые подтверждения; SimpleActor не выводит эти этапы автоматически из текста диалога. Это существующее ограничение, не изменённый учебный процесс.

## Что действительно меняют «Допустимые итоги»

Галочка меняет список `allowed_outcomes` во встроенном исходном сценарии версии карточки клиента. Она разрешает вариант для проверки, не требует согласия клиента и не подтверждает наличие услуги/цены/срока.

| Галочка действующей компании | Смысл разрешённого варианта |
| --- | --- |
| Обоснованное отсутствие подходящей услуги (`no_fit`) | Допустим мотивированный итог без подходящего предложения |
| Lieferung (`lh_sv_01`) | Допустим итог с доставкой на подтверждённых условиях |
| Standard-Einbau Backofen (`replacement`) | Допустим итог со стандартным монтажом духовки |
| Standard-Einbau integrierter Geschirrspüler (`lh_sv_03`) | Допустим итог с монтажом встроенной посудомоечной машины |
| Anschluss freistehender Geschirrspüler (`lh_sv_04`) | Допустим итог с подключением отдельностоящей посудомоечной машины |
| Anschluss Waschmaschine (`lh_sv_05`) | Допустим итог с подключением стиральной машины |
| Altgerätemitnahme im Übungspaket (`lh_sv_06`) | Допустим итог с вывозом старой техники в рамках пакета |
| Vor-Ort-Prüfung der Einbausituation (`lh_sv_07`) | Допустим итог с осмотром места установки |
| Diagnose elektrisches Haushaltsgerät (`diagnosis`) | Допустим итог с диагностикой |
| Reparatur (`repair`) | Допустим итог с ремонтом, без выдуманного обещания результата |

Важное фактическое ограничение: старт с парой «библиотечный сценарий + клиент» заменяет встроенный сценарий выбранным библиотечным. Поэтому локальные галочки карточки НЕ публикуют библиотечный сценарий и НЕ меняют его допустимые итоги в новой попытке. Это теперь прямо написано рядом с настройкой. Никакого автоматического перепривязывания сценариев к новым услугам нет.

Снимок фактически выбранного сценария используется в построении отчёта (`assessment_outcomes`) и старом ручном поле `outcome` с проверкой разрешённых ID. Предварительный ИИ-разбор наставника получает сценарий из снимка; клиентский Actor списка не получает. Текущая независимая проверка наставника записывает отдельный качественный `commercial_outcome`, не вычисляет его из галочек. Демо/старый сценарный движок может использовать список в своих ветвлениях, SimpleActor не превращает галочки в обязательное согласие. Ни одна галочка не выдаёт сертификат, не публикует отзыв и не означает автоматический успех.

Предложение следующего этапа: отдельно утвердить, где наставник редактирует действующие итоги библиотечного сценария и как связать это с карточкой клиента. Не менять это неявно при оформлении/импорте.

## Компания и импорт

Описание и ограничения — свободный текст. «Политика и условия компании» редактирует тот же черновик ограничений; две формы синхронизированы. Услуги редактируются в существующем единственном списке; прейскурант строится из него. Для товаров явная кнопка открывает существующий табличный механизм импорта с текущим каталогом и добавлением строк. Обычные пояснения справа свёрнуты в «Помощь по заполнению», влияние на старые беседы оставлено кратко.

Без изменений кнопка отключена и показано «Все изменения сохранены». Точный возврат исходных данных снова отключает её; успешное сохранение обновляет baseline; ошибка сохраняет черновик. Изменение компании атомарно создаёт версию материалов и синхронизирует услуги. Снимки прошлых попыток не переписываются.

«Документы → Добавить файл» использует прежний импорт. Назначения: описание, товары, услуги, политика/условия, справочный документ. Файл сначала извлекается и сохраняется как оригинал; просмотр/маппинг/ошибки предшествуют явному подтверждению применения. По умолчанию «Добавить/обновить» сохраняет прежние записи и неуказанные поля совпавшего товара. «Заменить» явно показывает удаляемые названия/артикулы до подтверждения. Несовпадающие ID/артикулы не объединяются по похожему имени. Без ID создаётся новая запись с предупреждением; повторные ID/конфликтные артикулы блокируют импорт. Сохранено только ранее утверждённое соответствие канонических услуг (`REFERENCES`), произвольные совпадения названий не используются.

Удаление услуги, на которую ссылается библиотечный сценарий или карточка, блокируется: нужна отдельная согласованная правка сценариев. Конкурентное изменение материалов отклоняет устаревший предпросмотр. Применение обновляет текущие материалы, карточку компании и новую версию в одной транзакции. Старые версии и оригинальные байты остаются. Справочный документ не становится политикой или прейскурантом. Обновление политики помечает прежние тексты как заменённые, сохраняя оригиналы; merge политики сохраняет прежние активные тексты, replace заменяет выбранное назначение.

Ограничения импорта сохранены: до 10 MB; до 200 строк/100000 символов; CSV с заголовками, XLSX один лист (до 50 столбцов, без вычисления формул; нужны сохранённые значения), MD/TXT, PDF только с текстовым слоем через локальный `pdftotext`. OCR, автоматического определения колонок PDF, внешней загрузки URL и ИИ-извлечения нет. Для PDF-таблицы нужен проверенный CSV/XLSX. Условия до 5000 символов; ограничения карточки/числа услуг продолжают действовать. Часть прежних диагностик импорта двуязычна EN/RU, полная локализация этих старых сообщений остаётся ограничением.

После правки исходника прежние переводы удаляются из актуальной версии и показывается необходимость обновления. Автоматическая платная генерация не запускается; старые снимки сохраняют свои переводы.
