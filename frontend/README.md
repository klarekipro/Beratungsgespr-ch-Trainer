# Frontend — локальный тренажёр консультации

Функциональный интерфейс на HTML/CSS/JavaScript без сборки, внешних шрифтов или CDN. FastAPI обслуживает `index.html` на `/`, остальные файлы — на `/static/`. API и интерфейс работают на одном origin.

## Два рабочих пространства

- **Ученик:** выбор клиента и режима, история/продолжение беседы, вопросы и резюме, итоговое предложение, завершение, разбор, PDF/TXT/JSON, передача наставнику и просмотр отзыва.
- **Наставник:** карточка компании с услугами/условиями/ограничениями, источник и вставленный текст с сайта, создание/редактирование/удаление сценариев, скрытые факты и неопределённости, план вопросов, очередь отправленных бесед и письменная обратная связь.

Это два интерфейса одного локального владельца. Переключатель пространства и заголовок `X-Workspace-Role` не являются аутентификацией нескольких пользователей. API-ключ не вводится в интерфейс, не передаётся клиенту и не хранится в LocalStorage. LocalStorage содержит только предпочтение рабочего пространства.

## Режимы беседы

**Техническая проверка** (`mode: demo`, прежнее название «Сценарный режим») использует ограниченный распознаватель и подготовленные ответы. Она предназначена для проверки интерфейса и переходов, а не для свободного разговора или оценки навыка сотрудника. Это прямо указано до начала, над диалогом и над разбором. Кнопки запуска и повтора называют технический режим. Точные примеры находятся в `backend/app/dashboard/seeds.py` в `DEMO_WALKTHROUGH`; приватные ответы не показываются в активной ученической сессии.

**OpenAI** выбирается по умолчанию для новой беседы, когда сервер сообщает одновременно `ai.configured` и `ai.live_enabled`. Явно выбранная техническая проверка сохраняет выбор при навигации в текущей странице; предпочтение режима не записывается в LocalStorage. Если OpenAI недоступен, интерфейс объясняет, что доступна только техническая проверка. Статус запрашивается заново при навигации и обновлении, поэтому перезапуск сервера с ключом не оставляет интерфейс со старым состоянием конфигурации.

**Созданная беседа сохраняет свой режим.** Подключение ключа не превращает прежнюю demo-попытку в OpenAI. В её диалоге и разборе есть заметное пояснение и, когда OpenAI настроен, кнопка начала отдельной новой беседы. Старая попытка остаётся в истории. Повтор прежнего технического случая обозначен отдельно; OpenAI-попытки не повторяются в demo незаметно.

Наличие конфигурации не выдается за успешную платную проверку API. При ошибке API интерфейс сохраняет реплику для явного повтора и не переключает пользователя в технический режим. Фактическое качество модели требует отдельной проверки.

Над OpenAI-диалогом и разбором отображаются фактические серверные счётчики: `natural_customer_turns` как «Разговорных AI-ответов» и `api_requests` как «Запросов API». Неизвестный счётчик отображается как «нет данных», а не как ноль. Старые OpenAI-попытки с распознаванием вопросов и готовыми репликами могут иметь ноль разговорных AI-ответов. Серверный `ai.max_requests_per_turn` показан перед новой OpenAI-беседой и в настройках; текущий полный ход использует три последовательных запроса — распознавание, ответ клиента и проверку содержания.

## Существенные сведения и справочные детали

В редакторе факта есть отдельный флажок «Влияет на итоговое решение» (`material`). У старых карточек без этого поля значение по умолчанию — `true`; явное `false` сохраняется. Новые факты создаются с `material: true`.

Обязательный факт всегда существенен. Пока включено «Обязательно выяснить перед завершением этапа», флажок значимости отмечен и недоступен для снятия. После снятия обязательности наставник может сделать факт справочным. Необязательное существенное ограничение нужно учитывать в резюме после его раскрытия; справочную деталь повторять необязательно.

## Данные и поведение

- Каталог ученика и активный диалог используют публичные API views; полный сценарий загружается только в редакторе наставника.
- Версии карточек фиксируются сервером для каждой беседы. Редактирование компании или сценария не переписывает старую попытку.
- Повтор отправки сообщения использует тот же `request_id`; после конфликта версии загружается актуальная беседа.
- Незавершённую попытку можно закончить с неполным результатом. Скрытые факты и экспорт появляются только после завершения.
- «Отправить наставнику» добавляет беседу во внутреннюю очередь, не отправляет email или сообщения во внешние системы.
- Вёрстка адаптирована для телефона, планшета и desktop. Используются системные шрифты, контрастный фокус, подписи полей, клавиатурная навигация и нативный диалог подтверждения завершения.

Контракт API: [DASHBOARD_API.md](../docs/implementation/DASHBOARD_API.md). Запуск сервера — по основной инструкции приложения. Открывать `index.html` через `file://` не нужно: интерфейсу требуется локальный Python-сервер.

## Быстрая проверка JavaScript

```sh
node --check frontend/app.js
```

Синтаксическая проверка не заменяет проверку интерфейса в браузере и реальных маршрутов API.
