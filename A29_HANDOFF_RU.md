## Все найденные расхождения этого тракта

1. **Claim verdict и источник:** отсутствовал условный минимум1 для supported/contradicted. Теперь две ветви схемы; для остальных трёх verdict допустим0. Инструкция ограничивает claim_checks условиями/обещаниями компании: факт заказа/визита относится к actual_outcome/этапам, а не к противоречию политике.
2. **Этап и ссылка:** схема допускала evidence_found без evidence. Теперь отдельные ветви с минимум1/0 соответственно.
3. **Повтор и finding_refs:** инструкция/схема требовали только gaps, сервер проверял лишь наличие хотя бы одного gap. Теперь один контракт требует все ссылки на gaps. Нет автоматической подмены рекомендации.
4. **Индексы/пустой текст:** для stages находился общий максимум индекса7 вместо2; minLength1 допускал пробелы, отклонявшиеся `.strip()`. Теперь индексы разделены по section, задан pattern `\S`. Динамическое попадание индекса в реально созданный список остаётся серверной проверкой.
5. **Дублирование структуры:** отдельные ручные проверки полей/лимитов расходились со схемой. `review_contract.py` — единая фабрика wire/bound схем и проверка ровно используемого JSON-schema подмножества. Неизвестные keywords/patterns отклоняются. Wire проверяется до binding, bound — после. Общие `$defs` убирают повтор enum источников и ID. Текущая схема13398 символов вместо10935 в A28; полный payload остался29372. Внешних библиотек/модельных вызовов не добавлено.
6. **Короткие/числовые источники:** прежний фильтр строк длиной12 исключал реальные короткие цены и числовые поля. Теперь доступны точные непустые строковые/скалярные значения исторического payload. Для короткого источника нужна полная цитата, для длинного сохранён прежний минимум12 и дословное соответствие. Произвольный модельный quote в wire по-прежнему запрещён; сервер привязывает точное значение. При полном отсутствии материалов схема не допускает supported/contradicted и ненастоящий источник; пустой транскрипт отклоняется до провайдера.
7. **Старые цитаты/экспорт:** отсутствующий quote у старой ссылки теперь читается только из исходного снимка этой попытки, включая старые поля материалов, отсутствующие в новом компактном payload. Это проекция при чтении, без миграции и без сегодняшней компании. Недоступный источник подписан DE/EN/RU вместо пустого blockquote; TXT/PDF также явно помечают retained result после ошибки refresh.
8. **Диагностика:** теперь фиксируются request_strict, request_format и SHA схемы; protected capture/replay учитывает hash и review_service, и нового review_contract. Содержимое разговоров/ключи в обычный лог/интерфейс не выводятся, прежние ограничения capture сохранены.

### Итоговая структурная спецификация

Все object-поля обязательны, лишние поля запрещены. Enums:3 ключа этапов,3 статуса доказательств,5 verdict компании,3 действия, sections strengths/gaps/next_attempt/stages. ID сообщений и paths выбираются из сохранённого контекста.

Отдельно сохранены: уникальность трёх ключей этапов, фактические границы ссылок на созданные списки, точное соответствие цитат оригинальным сообщениям/материалам и отсутствие замены исторического контекста. Схема/ссылки **не доказывают фактическую корректность или уместность выбранной цитаты**. Семантическая калибровка/окончательное решение остаются задачей ИИ-разбора и наставника соответственно; ложный booking в новом claim не исправляется сервером «в успех».

## Проверка кажущихся пустыми цитат

В retained успешном анализе реально сохранены две цитаты длиной128 и122 символа. На отдельной копии обе присутствуют в learner API, JSON и TXT. PDF возвращает корректный документ из того же report_text; извлечение текста из PDF отдельно не выполнялось. `old-quote-report.json` подтверждает отсутствие переписывания записи.

На синтетическом браузерном стенде воспроизведено: закрытые details исключают цитату из видимого копируемого текста, раскрытые показывают её целиком. Wire/capture по контракту содержит path без quote; quote появляется после серверного binding. Для прежнего успешного результата потери binding/экспорта не обнаружено. Точный способ копирования владельцем неизвестен. В UI добавлено число источников, сохранены раскрытие и «Посмотреть»; для path-only старых записей проверено восстановление из снимка.
