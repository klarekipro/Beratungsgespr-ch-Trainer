# User Roles & Flows — роли, доступ и пользовательские пути

**Статус: DESIGN PROPOSAL.** Экранные функции и роли предложены для обсуждения. Dashboard и реализация не утверждены.

Дата: 2026-11-05. Baseline: `2962a1b89cb8c9816decc8322ec92259993b3b03`.

Источники: [оригинальный PDF](<../product/Beratungsgespräch-Trainer — описание продукта.pdf>), стр. 2–5 и 7; [handoff](../PROJECT_HANDOFF_FOR_ASTRA.md), разделы 1–3, 7–8; [known issues](../KNOWN_ISSUES.md), FACT-001, PRODUCT-001, APP-001. Описанные ниже потоки ещё не реализованы в baseline.

## 1. Принцип доступа

Личная тренировка предназначена ученику. Право редактировать сценарии не предоставляет автоматического права читать чужие диалоги. Возможность технического администрирования не превращается в функцию скрытой оценки работников.

Один аккаунт может совмещать несколько способностей. Например, Сергий в L1 — ученик, автор карточек и администратор своей установки. Но переключение режима в интерфейсе не является проверкой доступа: сервер проверяет пользователя, владение сессией и разрешённое действие при каждом обращении.

### Роли и способности

| Роль / способность | Назначение | Доступ к результатам |
|---|---|---|
| **Ученик** | Самостоятельная тренировка, просмотр своего разбора, повтор, управление своими данными | Только собственные сессии; скрытые сведения своей карточки открываются после завершения |
| **Автор сценариев / тренер L1** | Создание и редактирование карточек, проверка и утверждение новых версий, preview | Собственные или синтетические preview-сессии и их журнал; не все диалоги учеников |
| **Тренер-наставник L3** | Комментарий к добровольно предоставленному результату, назначенные учебные материалы | Только явно предоставленный объём конкретного ученика; отдельное право, не следствие авторства карточки. L2 сохраняет личную практику без этой функции |
| **Технический администратор** | Доступ, конфигурация, лимиты, эксплуатация, обработка удаления/восстановления | По умолчанию служебные метаданные без текста; исключительный доступ к данным ограничен, обоснован и учитывается |

Публичная самостоятельная регистрация, приглашения групп, роли организации и наставничество не обязательны L1. Для доступного по сети режима всё равно нужен защищённый доступ. Конкретная схема входа утверждается вместе с режимом эксплуатации, см. [SECURITY_AND_GDPR](SECURITY_AND_GDPR.md).

### Матрица действий

| Действие | Ученик | Автор сценариев | Наставник | Администратор |
|---|---|---|---|---|
| Читать публичную карточку утверждённого клиента | Да | Да | Да | При наличии пользовательского доступа |
| Читать скрытые сведения во время самостоятельной тренировки | Нет | Только в редакторе/preview своей разрешённой карточки | Не через ученическую сессию | Не через обычный мониторинг |
| Читать полный разбор своей завершённой сессии | Да | Да для собственных сессий | Да для собственных сессий | Если сам владелец сессии |
| Создавать/редактировать карточку | Нет | Да в пределах доступной библиотеки | Только при отдельном авторском праве | Только при отдельном авторском праве |
| Изменить карточку уже начатой сессии | Нет | Нет; создаётся новая версия | Нет | Не как штатная операция |
| Читать журнал чужой личной тренировки | Нет | Нет по умолчанию | Только по отдельному предоставлению ученика на последующих уровнях | Исключительные операции по правилам безопасности, не учебная функция |
| Удалить свою тренировку / запросить удаление | Да | Да для собственных данных | Да для собственных данных | Выполнить корректно авторизованную операцию |
| Настраивать провайдера, секреты и пределы расходов | Нет | Нет | Нет | Да через защищённую конфигурацию |
| Строить рейтинг работников или принимать кадровое решение | Нет | Нет | Нет | Не предусмотрено назначением продукта |

## 2. Разделение режимов

Предлагаются следующие метки контекста попытки:

- **Самостоятельная тренировка:** ученик получает только открытую исходную ситуацию.
- **Повтор:** ученик уже мог видеть секреты этой версии после предыдущего разбора; полезен для практики формулировок, отдельно интерпретируется при анализе прогресса.
- **Preview автора:** автор проверяет карточку и журнал; не включается в личные достижения или аналитику обучения.
- **Тренировка с подсказками:** возможное последующее расширение. В L1 живые подсказки по скрытым темам не предлагаются; если режим появится, он не смешивается с самостоятельным.

Эти метки не должны усложнять первый вход. Пользователь видит понятное пояснение в нужный момент; технические признаки сохраняются в данных сессии. Для L1 достаточно различать самостоятельную попытку/повтор и авторский preview.

## 3. Основной путь ученика

### Шаг 1. Выбрать клиента

На стартовом экране ученик видит минимум три утверждённые карточки, название, сферу и краткую открытую ситуацию. Скрытые факты, их значения и цепочки открытия в ученический браузер не отправляются.

Для Herr Krüger открытая карточка должна соответствовать принятой версии, а не смешивать PoC с иллюстрацией PDF. «Снова», «со вчерашнего утра» или маленькая печь не появляются автоматически. Основание: [PRODUCT-001](../KNOWN_ISSUES.md), [handoff](../PROJECT_HANDOFF_FOR_ASTRA.md), раздел 2.

### Шаг 2. Получить короткий инструктаж

Показываются роль ученика, задача разговора, обозначение AI-симуляции, язык диалога, язык разбора и способ завершения. Ориентир 10–15 минут — ожидаемая длительность, а не обязательный таймер давления. Пользователь получает короткое указание использовать вымышленные сведения и не вводить данные настоящих клиентов.

**Уточнение для владельца:** PDF говорит «до 15 реплик», не определяя единицу. Рекомендуется максимум **15 успешно завершённых ходов ученика с ответами клиента**. Вступление, повтор доставки и технические ошибки не расходуют ход. До утверждения это предложение, не установленное требование. Вместо «15 вопросов» корректнее «15 сообщений/ходов»: ученик может задавать вопрос, уточнять или подводить итог.

Предложение по языкам L1: разговор на немецком; разбор DE/RU; понятная лексика интерфейса для A2–B2. Дополнительные языки и сложность речи — отдельно проверяемые расширения.

### Шаг 3. Вести разговор

Ученик читает реплику и отправляет собственный ответ. Пока система готовит ответ, показано ясное состояние ожидания. Ввод и доставка организованы так, чтобы двойное нажатие, потеря ответа или перезагрузка не создали два независимых хода и не списали два хода лимита. Детали — в [SYSTEM_ARCHITECTURE](SYSTEM_ARCHITECTURE.md).

Во время разговора нет списка A/B/C, счётчика «осталось выяснить» или индикатора, который выдаёт скрытую тему. Диалог может становиться осторожнее в соответствии с политикой сценария, но UI не показывает внутреннее решение Director.

Содержательно подходящий вопрос должен оцениваться по смыслу, включая несовершенный немецкий. Неясный ввод вызывает естественную просьбу клиента уточнить; эвристическая проверка языка не должна блокировать смешанный текст или превращать его в штраф. Автоматическое сочинение/перевод полного вопроса за ученика не включено в базовый L1.

### Шаг 4. Завершить

Ученик может закончить раньше лимита. Перед открытием разбора понятно объясняется, что скрытая информация станет видимой и текущая попытка завершится. После раскрытия секретов эта же попытка не продолжается как независимая тренировка.

Сессия фиксирует сценарную версию и свои события. Позднее редактирование карточки не меняет полученный результат. При завершении до лимита не нужен искусственный «штраф за короткий разговор»: качество определяется тем, что удалось выяснить и согласовать в рамках задачи.

### Шаг 5. Прочитать разбор

Рекомендуемая последовательность:

1. Понятное описание результата и статуса полноты данных.
2. Каждая скрытая потребность: что выяснено, что частично, что пропущено; ссылка на вопрос и фактический ответ клиента.
3. Отдельный блок AI-наблюдений о разговоре с короткими цитатами и объяснением.
4. Один основной фокус следующей попытки и несколько немецких фраз для практики.
5. Повторить этого клиента или выбрать нового.

Для потребностей предлагаются состояния **«Выяснено»**, **«Выяснено частично»**, **«Не выяснено»**, **«Не удалось оценить»**. Составные A/C требуют учёта реально озвученных частей. Событие разрешения само по себе не даёт полный результат. Если подходящий вопрос не получил корректного ответа из-за системы, объяснить это отдельно; не обвинять ученика.

Значение «1 из 3» показывается только тогда, когда правила полноты и данные позволяют его вычислить. Неизвестность не заменяется нулём. Качественные AI-советы — подсказки, а не сертификат, психологическая характеристика или объективный итоговый балл.

### Шаг 6. Повторить

Повтор создаёт новую сессию с зафиксированной версией. Ученик может попробовать более подходящие формулировки. Для проверки переноса навыка предлагается новый клиент; повтор известной карточки не смешивается с первой попыткой в будущей аналитике.

## 4. Ошибки, прерывание и честный результат

| Ситуация | Поведение для ученика | Что не допускается |
|---|---|---|
| Временная задержка/тайм-аут | Сохранить его текст, показать ожидание или возможность безопасного повтора | Исчезновение текста, скрытый второй ход, автоматический учебный штраф |
| Повторный запрос того же хода | Вернуть тот же уже зафиксированный результат либо продолжить известное состояние | Повторное раскрытие/списание лимита как новый вопрос |
| Director не дал валидного основания для новых фактов | Сохранить границу закрытой карточки; естественное уточнение или предусмотренное восстановление | Открыть секрет «на всякий случай» |
| Проверка обнаружила неподтверждённый ответ Actor | Не выдавать его как принятую реплику; использовать предусмотренное восстановление, иначе честно остановить ход | Показать обнаруженную выдумку и позже считать её находкой ученика |
| Страница перезагружена | Вернуть собственную текущую сессию и статус хода при действующем доступе | Доступ к сессии по угаданному ID или потеря принятого хода |
| AI-комментарий разбора недоступен | Показать доступный фактический результат с пояснением, что советы не готовы | Полностью выдумать оценку или вывести «0 потребностей» из-за технической ошибки |
| Достигнут предел расходов/доступности | Понятное сообщение о паузе, сохранение результата и возможность завершения в допустимом режиме | Бесконечные повторы запросов, скрытые расходы и ложное завершение |
| Доступ к чужому результату отсутствует/отозван | Сообщение об отсутствии доступа без деталей содержимого | Подсказки о названии/тексте чужой сессии |

Тексты UI описывают результат для человека. Имена моделей, HTTP 503, confidence и внутренние состояния остаются в ограниченной диагностике; ученику достаточно «Ответ сейчас не получен. Ваше сообщение сохранено».

## 5. Путь автора сценария / тренера L1

1. Открыть доступное авторское рабочее место.
2. Создать или скопировать черновик карточки.
3. Заполнить публичную ситуацию, скрытые атомарные сведения, условия раскрытия в разрешённой схеме, характер и допустимую реакцию на давление.
4. Проверить отсутствие противоречий и утечки скрытого через вступление/подсказки. Отдельно проверить темы, которые карточка не разрешает уточнять конкретными вымышленными деталями.
5. Запустить собственный synthetic preview, просмотреть журнал вопрос → решение → разрешение → действительно показанная реплика. Это авторская проверка, не ученический результат.
6. После сценарных проверок утвердить новую неизменяемую версию. Она становится доступна новым тренировкам.
7. Для изменений создать следующий черновик; старые сессии остаются на прежней версии. Архивирование убирает карточку из нового выбора, не переписывая историю.

Простой редактор L1 работает в рамках принятой схемы потребностей, а не как произвольный конструктор любых AI-агентов. Он не превращает любую заполненную форму в проверенный сценарий. Три клиента должны иметь собственные примеры вопросов, ожидаемые раскрытия и проверки Actor. Результат Director 74/74 нельзя автоматически переносить на новые темы или новые параметры.

Сам пользовательский режим автора не даёт права просматривать личные сессии всех учеников. В L1 журнал предназначен его собственным/синтетическим проверкам. Это одновременно сохраняет функцию «режим тренера» из PDF, стр. 5, и приватность ученика из PDF, стр. 2.

## 6. Добровольное предоставление результата на последующих уровнях

Наставничество предлагает отдельный путь: ученик выбирает конкретный результат, видимый объём, получателя и срок; получает понятное подтверждение; может отозвать будущий доступ. Тренер видит только предоставленное, а не все попытки человека. Новый результат не становится общим автоматически.

Отзыв блокирует дальнейшее получение через приложение, но не может гарантированно забрать уже сделанную внешнюю копию. Это ограничение нужно объяснить до предоставления. Экспорт и внешняя пересылка — самостоятельные действия ученика. Система работодателя для рейтинга, экзаменационного отсечения или кадровых решений не предлагается.

Права на пользовательские данные, правовое основание и правила образовательной организации рассматриваются отдельно в [SECURITY_AND_GDPR](SECURITY_AND_GDPR.md). Само согласие на педагогическое предоставление в UI не подменяет всё правовое основание обработки.

## 7. Доступность и понятный язык

Предлагаемые критерии UI для A2–B2:

- Короткие инструкции, знакомые слова, один основной следующий шаг; профессиональные термины объясняются рядом.
- Немецкий диалог и выбранный язык разбора различаются явно; немецкие примерные фразы сохраняются в обоих языках разбора.
- Операции доступны с клавиатуры; фокус видим; поля имеют текстовые подписи; статус ошибки передаётся текстом и не зависит только от цвета.
- Текст и кнопки остаются читаемыми на телефоне; длинные реплики переносятся; отправка не теряется за экранной клавиатурой.
- При новом ответе сохраняется понятная позиция чтения; важное сообщение о состоянии не исчезает мгновенно.
- Нет обязательного жёсткого таймера, живого рейтинга или наказания за медленное чтение.
- Помощь объясняет использование интерфейса, но не подсказывает актуальный скрытый факт.

Упрощение речи Actor до конкретного языкового профиля — отдельная проверяемая настройка. Оно не должно менять факты, правила раскрытия или сложность самой консультационной задачи без версии сценария. A01 не обещает языковой экзамен, определение CEFR или педагогическую сертификацию.

## 8. Навигация, помощь и управление своими данными

Минимальная навигация: **Тренироваться**, текущая сессия/разбор, **Помощь и мои данные**; **Карточки клиентов** автора видны только при его праве. «История» и «Прогресс» появляются после принятия соответствующих функций. Полный перечень экранов и приоритеты — в [DASHBOARD_PROPOSAL](DASHBOARD_PROPOSAL.md).

Помощь включает цель симуляции, правила завершения, отличие фактического результата от AI-совета, объяснение повторов и доступный способ обратиться по проблеме. Она не раскрывает карточку текущего клиента.

Настройки и данные: язык, понятный срок хранения, удаление своей тренировки и канал запроса удаления аккаунта/данных. Публичная форма регистрации, биллинг и полный профиль не нужны закрытому личному MVP. Точное правило хранения утверждается владельцем, а не выбирается самим UI.

## 9. Предлагаемая приёмка пользовательских путей

Следующие проверки являются будущими критериями, **не результатами A01**:

| Проверка | Ожидаемый результат |
|---|---|
| Ученик открывает карточку и вкладку Network до завершения | В ответах нет закрытой карточки, скрытых значений, промптов Director или авторского журнала |
| Автор меняет черновик во время чужой активной тренировки | Активная сессия и последующий разбор используют прежнюю зафиксированную версию |
| Ученик задаёт подходящий вопрос с ошибкой немецкого | Смысл может быть распознан; грамматика не становится автоматическим нулём результата |
| Actor не озвучил часть A/C | Разбор не показывает полное выявление по одному разрешению |
| Ответ API потерян, ученик повторяет отправку | Не создаётся дублирующий ход; результат/статус согласован с сервером |
| AI-комментарий недоступен | Фактическая часть и статус полноты показываются честно, без придуманного совета |
| Автор смотрит preview и затем личный прогресс | Preview не учитывается как самостоятельное достижение |
| Тренер пытается открыть непредоставленную чужую сессию | Доступ отклонён; владение сценарием не меняет результат |
| Ученик завершает, видит скрытые факты, нажимает повтор | Создаётся новая отмеченная попытка; завершённая не становится снова «слепой» |
| Работа на телефоне и только клавиатурой | Можно выбрать клиента, отправить сообщение, закончить и прочитать разбор без потери управления |
