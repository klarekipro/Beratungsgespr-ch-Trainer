# A01 — Каталог 16 модулей

**Статус:** проект, не перечень уже реализованных функций. **Дата:** 2026-11-05. **База:** `2962a1b89cb8c9816decc8322ec92259993b3b03`.

Это 16 логических модулей одного приложения. Frontend и Dashboard объединены: Dashboard является представлением данных, а не самостоятельным вычислителем оценки. Безопасность/доступ/удаление объединены в M12, но обязательны во всех модулях. Добавлены M06, обеспечивающий контролируемый состав ответа, и M16, управляющий качеством и доказательствами. Administration M15 отвечает за выпуск и эксплуатационные настройки, а не дублирует создание сценариев M01.

Сложность — относительная инженерная оценка: **S** локальная функция; **M** несколько контрактов; **L** критическая граница/интеграция; **XL** неопределённое качество моделей или коммерческие требования. Это не обещание длительности. Все критерии готовности ниже — **будущие gates**, не результаты A01. API пути — предлагаемые, их ещё нет.

## M01 — Scenario Management: карточки и библиотека

- **Назначение:** обеспечить единую проверенную фактическую основу каждого виртуального клиента.
- **Функции:** публичная ситуация, скрытые атомы, условия раскрытия, persona, речевые варианты, rubric; черновик/preview/publish/archive; новые версии вместо правки действующей; выбор опубликованных карточек.
- **Вход:** структурированная карточка автора, schema_version, review, positive/negative вопросы; исторический Krüger переносится с сохранением происхождения.
- **Выход:** неизменяемый ScenarioVersion и отдельные public/actor/evaluation представления; ошибки валидации с полями.
- **Зависимости:** M11 для хранения, M12 для прав, M15 для release, M16 для acceptance; M04 потребляет факты, M07 — rubric.
- **API/модели:** `/scenarios`, `/author/scenarios`; генератор карточек в L1 отсутствует, LLM не обязательна.
- **Безопасность:** закрытые атомы не входят в public DTO; нет исполняемых шаблонов/произвольных инструкций; author видит только свой scope.
- **Проверки:** ссылки atoms/segments, намеренные утечки в public, редактирование опубликованной версии, чужой scenario_id, три утверждённые карточки; ручной review смысла.
- **Сложность:** M для схемы, L для полезного контента и редактора.
- **Готовность:** три опубликованных клиента проходят content/eval gate; изменение карточки не меняет старую сессию. Неутверждённый клиент недоступен ученику.

## M02 — Dialogue Session Manager: жизненный цикл и ход

- **Назначение:** надёжно провести одну попытку от старта до разбора.
- **Функции:** фиксирует версии, номера ходов, mode, state и завершение; координирует Director/Policy/Actor; reservations, идемпотентность, восстановление после перезагрузки; запрещает продолжение после reveal.
- **Вход:** owner из доступа, scenario_version, текст, client_turn_id, expected_version; результаты M03–M06.
- **Выход:** ровно один committed-turn с сообщениями/событиями либо явный технический статус без фиктивного продвижения.
- **Зависимости:** M03, M04, M05, M06, M10–M14; по finish вызывает M07.
- **API/модели:** `/sessions`, `/turns`, `/finish`; собственная LLM не нужна.
- **Безопасность:** браузер не присылает trusted state/history; lease и fencing-token; один pending turn; проверка owner/status/version при commit.
- **Проверки:** двойной click, два окна, обрыв до/после commit, рестарт worker, timeout Actor, одновременные finish/delete/turn.
- **Сложность:** L.
- **Готовность:** все fault-injection тесты сохраняют инварианты; replay возвращает идентичный сохранённый ответ без новой генерации; сбой не увеличивает discovered-count.

## M03 — Director Engine: смысл вопроса

- **Назначение:** определить, какую учебную тему действительно затронула текущая реплика.
- **Функции:** multi-label классификация, причины/цитаты, неопределённость; разделяет текущий вопрос и прежние разрешения; обрабатывает pressure; новый L1-профиль в том же вызове выделяет наличие/тип предложения решения.
- **Вход:** текущий текст, разрешённый контекст и утверждённые критерии; legacy-профиль использует проверенный формат.
- **Выход:** валидируемое решение A/B/C/PRESSURE/NONE; для нового `director-vnext` также `solution_proposal` с типом и проверяемым span, либо типизированная ошибка/uncertain. Legacy schema/prompt остаются отдельным benchmark. Уверенность не является вероятностью.
- **Зависимости:** M13, M14, scenario profile из M01; решение применяет только M04.
- **API/модели:** внутренняя операция classify через provider; историческая модель закреплена в baseline, новая модель требует отдельного eval.
- **Безопасность:** без скрытых значений, tools и direct DB-write; вход пользователя недоверенный; причины не отправляются Actor/ученику во время упражнения.
- **Проверки:** legacy 74 и прежние восемь ошибок; новые перефразирования, отрицания, mixed labels, опечатки, A2/B1 формулировки, injection, uncertain; новые карточки отдельно.
- **Сложность:** L/XL из-за семантического качества.
- **Готовность:** не регрессируют обязательные legacy-сценарии; нет ложного разрешения на критическом release-наборе; recall и uncertain измерены на новых случаях. 74/74 прошлого набора не заменяет новый gate.

## M04 — Policy & State Manager: разрешение и реакция

- **Назначение:** детерминированно управлять тем, что вправе сообщить клиент.
- **Функции:** валидирует enum/структуру/доказательства, вычисляет preliminary authorization, reaction, ограничения; определяет ранность конкретного offer по `required_before_offer` и before-state; ведёт отдельное событие раннего предложения, не смешивая его с PRESSURE; не считает LLM true гарантией истины.
- **Вход:** серверный сценарий, committed-state, DirectorDecision, policy_version.
- **Выход:** tentative state, allowed fact/atom IDs, response constraints, proposed events; финализирует M02.
- **Зависимости:** M01, M03, M11; M05/M06 используют только вычисленный subset.
- **API/модели:** чистая внутренняя функция; LLM и сеть отсутствуют.
- **Безопасность:** fail-closed для нового раскрытия при invalid/uncertain; никогда не доверяет списку разрешений из браузера; проверенный output не меняет secret card.
- **Проверки:** таблица переходов, NONE exclusivity, mixed labels/pressure, недопустимые IDs, monotonic permissions, некоммитнутый ход, immutable published-version.
- **Сложность:** M/L.
- **Готовность:** одинаковые inputs дают одинаковые outputs; запрет новой выдачи на невалидном решении; PRESSURE не удаляет историю и не блокирует навсегда все нормальные вопросы.

## M05 — Actor Engine: поведение клиента

- **Назначение:** выбрать уместную реакцию виртуального клиента на немецкий вопрос.
- **Функции:** persona, лаконичность, Sie, normal/guarded, уточнение неизвестного, выбор ответа по теме; в рекомендуемом L1 выбирает утверждённые речевые фрагменты.
- **Вход:** только ActorContextDTO: public, allowed atoms/segments, reaction и доверенная история.
- **Выход:** CandidateReplyPlan с IDs вариантов/актом; это ещё не текст для показа. Свободный Actor — альтернативный профиль под отдельный gate.
- **Зависимости:** M04, M06, M13; контекст строится сервером, не пользовательским frontend.
- **API/модели:** generate/select через M13; не обращается к поиску, CRM или другим инструментам.
- **Безопасность:** скрытая карточка отсутствует; IDs вне allowlist не принимаются; история пользователя не превращается в новые факты.
- **Проверки:** 13 исторических дефектных событий/4 уникальных входа, навязанные симптомы/цены/даты, атаки, роль клиента, осторожность и приемлемая живость с человеком.
- **Сложность:** L/XL; особенно naturalness.
- **Готовность:** полный выбранный release-набор завершён, нет критических grounding/role ошибок; человек принимает естественность. Один удачный ответ не закрывает gate.

## M06 — Grounding & Response Composer: проверенный состав ответа

- **Назначение:** связать каждый показанный факт с разрешённой карточкой и доказательством в журнале.
- **Функции:** проверка схемы/IDs/совместимости фрагментов; выбор утверждённых значений; сборка краткой реплики; manifest emitted atoms; допустимый fallback при неправильном выборе; буферизация до валидации.
- **Вход:** CandidateReplyPlan, allowlist, scenario/policy version, состояние темы/реакции.
- **Выход:** ReadyReply с текстом, segment_ids, emitted_atom_ids, mode и system-limit flags, либо блокировка показа.
- **Зависимости:** M01, M04, M05; M02 фиксирует, M07 использует manifest.
- **API/модели:** локальная функция; новый LLM-verifier не обязателен и не называется детерминированным.
- **Безопасность:** произвольный текст модели не попадает ученику в grounded-mode; публичные варианты тоже проверяются на смысловые утечки; никакого partial streaming.
- **Проверки:** неизвестные/повторные/запрещённые IDs, конфликтующие суммы, неуместное согласие на покупку, составные A/C, malicious segment content, отсутствие атома при claimed-output.
- **Сложность:** L с существенным редакционным трудом.
- **Готовность:** все разрешённые пути вывода используют approved corpus; manifest совпадает с фактическим текстом; acceptance включает семантический review самих фраз. Это ограниченный механизм, не универсальная защита от любых галлюцинаций.

## M07 — Evaluation & Feedback Engine

- **Назначение:** объяснить, что ученик выяснил, где остались пробелы и как улучшить вопрос.
- **Функции:** детерминированный core по required/emitted atoms; source question/answer; partial/uncertain/system-limited; отдельные советы о давлении, последовательности, Sie, следующем шаге; DE-примеры и DE/RU разбор.
- **Вход:** завершённая сессия, committed-events, закреплённые rubric/scenario и отдельный снимок ограничений незавершённых turn_requests; последний не даёт Finding/permission. AI-feedback получает минимально достаточный transcript.
- **Выход:** immutable core + отдельно версионированный advisory feedback с точными ссылками на реплики.
- **Зависимости:** M01, M02, M06, M11, M13; M08/M09 потребляют результат.
- **API/модели:** `/evaluation`; один дополнительный вызов Feedback optional, static сценарные рекомендации всегда доступны.
- **Безопасность:** hidden facts выдаются только владельцу завершённой сессии; цитаты сверяются; модель не меняет found и не выставляет кадровый/сертификационный балл.
- **Проверки:** authorized-but-unspoken, partial A/C, timeout, ложные цитаты, mixed languages, повторная генерация tips, некорректный ранний вызов.
- **Сложность:** L.
- **Готовность:** core повторяем по журналу; технический сбой не считается ошибкой ученика; каждый существенный AI-комментарий имеет свидетельство или явную неопределённость.

## M08 — User Progress & History

- **Назначение:** дать ученику видеть собственную практику и следующий учебный шаг.
- **Функции:** история сессий, просмотр старого разбора, сравнение сопоставимых попыток; отделение preview/repeat/assisted; агрегирование по потребностям, а не рейтинг людей.
- **Вход:** свои завершённые сессии и core results, версия rubric, настройки сохранения.
- **Выход:** личная timeline/summary; L1 только текущий сохранённый результат, полноценный экран истории факультативен по PDF.
- **Зависимости:** M07, M11, M12; M09 отображает.
- **API/модели:** `/me/sessions`, `/me/progress` позже; LLM не нужна для подсчёта.
- **Безопасность:** owner filters; срок хранения; удалённая сессия исключается из производных; неизвестные результаты не превращаются в нули.
- **Проверки:** чужой ID, разные rubric, одна/малая выборка, удаление/пересчёт, знакомый сценарий, прерванная сессия.
- **Сложность:** M; расширенная аналитика L.
- **Готовность:** пользователь понимает состав метрики; нет утверждений о росте навыка только по повтору знакомых ответов. Основной объём L2.

## M09 — Frontend & Dashboard

- **Назначение:** сделать выбор, разговор и разбор понятными на A2–B2 без технической перегрузки.
- **Функции:** навигация, карточки, чат, ожидание/восстановление, finish, разбор, форма сценария; Dashboard только выбранной владельцем глубины; адаптивность, keyboard, читаемый немецкий, DE/RU labels.
- **Вход:** публичные API DTO, состояния запросов, настройки языка; не raw internal-state.
- **Выход:** действия пользователя и доступное представление результата.
- **Зависимости:** M10, M12; данные M01/M02/M07/M08/M15.
- **API/модели:** same-origin fetch и серверные templates; ключей и прямых вызовов LLM в браузере нет.
- **Безопасность:** textContent/escaping, отсутствие скрытых фактов в HTML/network/localStorage, CSRF для cookie writes, минимум локального хранения.
- **Проверки:** клавиатура/mobile/zoom, не потерять ввод после 429/503, двойная отправка, закрытый режим автора, доступность, безопасные errors.
- **Сложность:** M для минимального, L для расширенного.
- **Готовность:** согласован Dashboard, весь цикл проходит без скрытых технических знаний; разработка UI до согласования не начинается. Перечень экранов — [DASHBOARD_PROPOSAL.md](DASHBOARD_PROPOSAL.md).

## M10 — Backend/API

- **Назначение:** предоставить стабильный контракт интерфейсу и будущему голосовому адаптеру.
- **Функции:** routing, request/response schemas, auth dependencies, error mapping, length limits, version/idempotency headers; отделяет публичные DTO от внутренних.
- **Вход:** валидируемые HTTP-запросы с авторизованной сессией доступа.
- **Выход:** стандартные data/error responses, request_id; status и Retry-After без раскрытия provider payload.
- **Зависимости:** M01/M02/M07/M12/M14; не реализует domain-policy повторно в endpoints.
- **API/модели:** FastAPI/OpenAPI `/api/v1`; внешняя модель только через M13.
- **Безопасность:** owner на каждом ресурсе, отсутствие mass assignment, same-origin, запрет browser-provided trusted roles/state, безопасный health-check.
- **Проверки:** schema/contract, 401/403/404 политика доступа, 409/422/429/503/504, CSRF, unknown fields, закрытые endpoint-ответы.
- **Сложность:** M.
- **Готовность:** публичный контракт и ошибки согласованы; integration tests подтверждают access и state invariants, а не только HTTP 200.

## M11 — Database & Persistence

- **Назначение:** сохранять сообщения, состояние, версии и доказательства согласованно.
- **Функции:** repositories, migrations, constraints, transactions, leases, atomic commit, restore; хранит данные из [DATA_MODEL.md](DATA_MODEL.md).
- **Вход:** проверенные доменные команды и параметры доступа.
- **Выход:** consistent snapshots и сохранённые результаты; техническая ошибка не оставляет половину хода.
- **Зависимости:** PostgreSQL; M12 правила ownership/deletion; M14 health/ops; все доменные модули используют узкие repository interfaces.
- **API/модели:** SQLAlchemy/Alembic, серверный DB connection; LLM нет.
- **Безопасность:** отдельный пользователь БД с нужными правами, закрытый порт, параметризованные запросы, encrypted backup, отсутствие raw dumps в Git.
- **Проверки:** constraints, rollback, concurrent write, migration/restore, interrupted transaction, cascade deletion, stable version binding.
- **Сложность:** L.
- **Готовность:** проверен реальный PostgreSQL, восстановление не воскресит удалённые записи; локальный fake не выдаётся за integration PASS.

## M12 — Identity, Access & Privacy

- **Назначение:** оставить контроль над тренировками ученику и ограничить обработку данных.
- **Функции:** owner identity, roles, authentication gate, session access, retention/deletion/export, sharing grant позднее, согласованные privacy settings.
- **Вход:** identity context, политики, запрос владельца данных, доступ автора/оператора.
- **Выход:** разрешение/отказ и проверяемое удаление/экспорт, минимальный audit без содержания диалога.
- **Зависимости:** M10/M11/M14/M15; поставщики и hosting проверяются перед внешним запуском.
- **API/модели:** `/auth/*`, `/me/*` для удалённого режима; L1 loopback owner; LLM для auth/доступа не используется.
- **Безопасность:** session cookies HttpOnly/Secure по HTTPS, CSRF, пароль/идентификация через проверенные средства; secrets вне repo; trainer не получает чужие результаты по роли.
- **Проверки:** cross-user IDOR, session lifecycle, consent/grant revoke, delete backups policy, export scope, логирование без секретов, удаление pending.
- **Сложность:** M для локального ограничения, L/XL для коммерческого сервиса.
- **Готовность:** локальный scope реально ограничен; до первого удалённого пользователя проходят auth/TLS/access/privacy gates. Правовые требования и открытые договорные вопросы — [SECURITY_AND_GDPR.md](SECURITY_AND_GDPR.md).

## M13 — AI Provider Gateway & Model Configuration

- **Назначение:** изолировать провайдера и управлять воспроизводимостью, расходом и ошибками.
- **Функции:** профили на роль, schema handling, usage, request IDs, deadlines, bounded retries, отказ без молчаливой смены модели, versioned prices/reserve.
- **Вход:** role task с минимальным контекстом, model profile, attempt/session budget, remaining deadline.
- **Выход:** typed result или timeout/rate-limit/refusal/incomplete/invalid error; usage-known отдельно от estimated cost.
- **Зависимости:** M12 secrets/data policy, M14 лимиты/метрики, M11 audit; вызывается M03/M05/M07.
- **API/модели:** сначала OpenAI Responses; второй адаптер лишь по продуктовой необходимости и собственной регрессии.
- **Безопасность:** провайдер видит минимальные поля, store=false где применимо; no tools; retention/residency проверены отдельно, не обещаются из параметра API.
- **Проверки:** contract/fault responses, SDK retries не умножают app retries, unsupported schema, исчезновение модели, usage missing, concurrent budget reservation.
- **Сложность:** M/L.
- **Готовность:** смена профиля не меняет старые сессии; бюджет проверяется до каждого request; реальные provider eval отдельно от offline tests.

## M14 — Observability, Limits & Error Recovery

- **Назначение:** видеть работоспособность и объяснимо переживать сбои.
- **Функции:** request correlation, received/usable/committed counts, p50/p95 latency, quotas, circuit breaker, recovery expired lease, alerts оператору без transcript.
- **Вход:** метаданные API/DB/turn/evaluation и настройки допустимой нагрузки.
- **Выход:** безопасные метрики, degraded-status, запрет лишних вызовов и восстановимые запросы.
- **Зависимости:** M02/M11/M13; UI получает человеческий статус через M10.
- **API/модели:** локальные структурированные логи и закрытая health/metrics поверхность; n8n/внешний SaaS не нужны L1.
- **Безопасность:** без текста prompts/ответов по умолчанию, короткий retention, no secrets in error stack, operators не видят лишнее.
- **Проверки:** timeout/429/503, crash recovery, lost response, missing usage, exhausted quota, budget race, purge logs.
- **Сложность:** M/L.
- **Готовность:** каждая ошибка имеет request_id и действие пользователя; прогресс не подменяется техническими успехами; расходы не исключают неизвестные попытки.

## M15 — Administration & Content Release

- **Назначение:** управлять качеством опубликованных сценариев и конфигурацией приложения.
- **Функции:** review/publish карточки, архивирование, profile activation, limits, проверка здоровья; коммерческие memberships/entitlements позднее.
- **Вход:** готовый draft M01, результаты M16, роль владельца/оператора, согласованные настройки.
- **Выход:** опубликованная version/profile с audit и обратимой деактивацией для новых сессий.
- **Зависимости:** M01/M11/M12/M13/M14/M16.
- **API/модели:** `/author/.../publish`, закрытая admin-конфигурация; LLM не принимает release-решение.
- **Безопасность:** отдельно author/operator privileges; отсутствие глобального просмотра личных результатов; непросматриваемые ключи, no self-grant через форму.
- **Проверки:** publish без review, устаревший revision, чужой draft, rollback только новых starts, audit без содержания личных диалогов.
- **Сложность:** M, коммерческие операции L.
- **Готовность:** плохая карточка/модель не публикуется автоматически; действующая сессия завершает работу на своей версии. Для L1 допускается владелец как автор и reviewer с честной фиксацией self-review.

## M16 — Quality & Evaluation Harness

- **Назначение:** доказуемо разделять качество кода, поведение моделей и продуктовую полезность.
- **Функции:** immutable legacy baseline, новые sanitized fixtures с provenance, deterministic tests, live eval plans, ручной rubric-review, version matrices, регрессия всех трёх сценариев.
- **Вход:** код/контент/profile версии, утверждённый test plan и отдельное разрешение на платные вызовы.
- **Выход:** PASS/FAIL/BLOCKED/INCOMPLETE на определённом наборе, знаменатели/пропуски, failure examples, наблюдённые usage/latency; без косметического изменения эталонов.
- **Зависимости:** все модули через контракт; приватный архив нужен только для исторических checks, не для будущих безопасных unit fixtures.
- **API/модели:** offline проверки без моделей; live отдельно и намеренно; CI не вызывает платный API автоматически.
- **Безопасность:** raw и секреты вне Git, синтетические карточки, approved test budgets, неизменность исходных results.
- **Проверки:** сам план различает API attempt/response/usable-result; отсутствующие данные дают INCOMPLETE/BLOCKED, не PASS; доли считаются по реальным denominator.
- **Сложность:** L/XL — включает смысловой и пользовательский review.
- **Готовность:** новый checkout выполняет новые детерминированные проверки без raw/ключа; исторические архивозависимые tests честно отделены; live evidence воспроизводимо описано. В A01 никакой live gate не закрыт.
