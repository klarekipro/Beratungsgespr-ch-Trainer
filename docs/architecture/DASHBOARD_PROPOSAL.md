# Dashboard Proposal — варианты функций и согласование

**Статус: DESIGN PROPOSAL / AWAITING OWNER DECISION. Dashboard не утверждён.** В этой миссии описаны варианты; интерфейс, HTML-шаблоны и production-код не создаются.

Дата: 2026-11-05. Baseline: `2962a1b89cb8c9816decc8322ec92259993b3b03`.

Основание: [оригинальный PDF](<../product/Beratungsgespräch-Trainer — описание продукта.pdf>), стр. 2–5 и 7; [handoff](../PROJECT_HANDOFF_FOR_ASTRA.md), разделы 1, 5, 7; [known issues](../KNOWN_ISSUES.md). Исходный PDF задаёт учебный цикл и режим тренера, но не утверждает окончательный Dashboard. Задание A01 требует остановиться после проектирования и обсудить его с владельцем.

## 1. Рекомендуемое решение для обсуждения

**Предлагается минимальный Dashboard для L1:** быстро начать тренировку, продолжить свою текущую сессию и открыть её разбор; автор получает отдельное рабочее место карточек и собственных preview-проверок.

Минимальность Dashboard не сокращает исходный MVP до одного клиента. В L1 сохраняются минимум **три утверждённых клиента**, простой **редактор карточки**, немецкий разговор, управляемое раскрытие, реакция на давление, разбор DE/RU и повтор. Эти функции заданы PDF, стр. 5. История всех прошлых тренировок остаётся опциональной, а графики прогресса предлагаются после проверки ядра.

Окончательный выбор остаётся за владельцем. Ни этот документ, ни создание ветки документации не считаются согласованием.

## 2. Роли Dashboard

### Ученик

Dashboard помогает выбрать одну практическую задачу и вернуться к своему результату. Он не должен выдавать скрытые потребности до завершения, провоцировать сравнение с другими людьми или выглядеть как кадровая оценка.

### Автор сценария / тренер

Автор управляет сценарными черновиками, утверждёнными версиями и проверками. Его право на карточку не открывает личные разговоры всех учеников. Для L1 журнал — собственные/синтетические preview-сессии. Доступ наставника к предоставленным учеником результатам является отдельной будущей функцией.

### Технический администратор

Ему нужны состояние сервиса, лимиты, ошибки и управление доступом. Для личного MVP эти операции не обязательно оформлять большим административным Dashboard. Текст диалогов не требуется обычному мониторингу.

Матрица доступа и пользовательские пути: [USER_ROLES_AND_FLOWS](USER_ROLES_AND_FLOWS.md). Продуктовый запрет на работодателя-оценщика следует из PDF, стр. 2; он сохраняется и при оплате доступа организацией.

## 3. Сравнение трёх вариантов

| Функция | Минимальный — L1 | Стандартный — L2 | Расширенный — L3 |
|---|---|---|---|
| Начать тренировку и выбрать клиента | Да, главный путь | Да | Да |
| Продолжить текущую сессию / открыть текущий разбор | Да | Да | Да |
| Утверждённая библиотека | Минимум 3 клиента | Расширение на основе личной практики | Библиотеки авторов/организаций с изоляцией и версиями |
| Простой редактор, preview и авторский журнал | Да | Улучшения удобства и контроля версий | Несколько авторов и правила публикации |
| История всех своих сессий | Опционально, только после ядра | Да | Да |
| Личные тенденции и план практики | Необязательны и не рекомендуются для критического пути L1 | Да, только сопоставимые попытки | Объяснимые рекомендации и задания |
| Предоставление результата наставнику | Не требуется | Не входит: личная практика и история | Отдельный добровольный grant, ограниченный доступ и комментарии наставника |
| Группы и учебные программы | Нет | Нет по умолчанию | Возможны после проверки назначения, прав и данных |
| Сводная аналитика | Нет | Только личная | Только согласованные учебные показатели с защитой малых групп и без кадрового ранжирования |
| Платежи / управление лицензиями | Нет | Не обязательно | Отдельный коммерческий модуль |
| Голос / AI-генератор клиентов | Нет | Не обязателен | Не автоматически; отдельные расширения L4 |
| Рейтинг учеников/работников, скрытый контроль | Нет | Нет | Не входит в назначение |

**Зависимости:** минимальному варианту нужны стабильное ядро, сессия, текущий разбор и карточки. Стандартному дополнительно нужны история, сопоставимость результатов и удобное управление данными. Расширенному нужны изоляция организаций, отдельное предоставление доступа, договорные и эксплуатационные процессы. Дизайн расширенного варианта не означает, что эти функции можно безопасно добавить за восемь дней.

## 4. Предлагаемое содержание минимального варианта

### Старт ученика

Первый экран содержит название и краткую цель, основную кнопку **«Начать тренировку»**, доступные открытые карточки и, при наличии, возможность продолжить собственную текущую сессию. После завершения доступен текущий разбор и повтор.

Наличие текущего результата не означает обязательную реализацию полноценной истории. Данные текущей сессии нужны для надёжного завершения и восстановления; каталог всех прошлых попыток — отдельная функция.

Перед стартом — краткое описание роли, AI-симуляции, немецкого диалога, выбранного языка разбора, ожидаемой длительности и правил данных. Пустое состояние говорит «Вы ещё не проходили тренировку», а не показывает нулевую оценку.

Не предлагаются как обязательные: серии ежедневных посещений, общий балл, проценты «успешности продавца», сравнение с другими, диаграммы по малой выборке и панель скрытых фактов во время разговора.

### Рабочее место автора

Список карточек с состоянием черновик/проверка/утверждённая версия/архив; действия создать, скопировать, редактировать черновик и открыть preview. Отдельная запись проверки показывает, что было проверено и где остаётся проблема. Наличие карточки в списке не означает её приёмку.

Авторский журнал нужен для связи вопроса, события разрешения и фактического ответа. Его технические подробности не добавляются в ученический чат. Все тестовые карточки и журналы обозначаются как синтетические; реальные клиентские сведения не требуются.

Простой редактор — реальная форма в рамках утверждённой схемы, а не универсальный генератор сценариев. Выбор только JSON-файлов вместо редактора должен обсуждаться как сокращение исходного MVP, а не называться той же функцией.

## 5. Полный перечень потенциальных экранов и состояний

Приоритеты: **обязательный L1** — нужен исходному учебному циклу/безопасному доступу; **желательный** — не задерживает приёмку ядра; **перспективный** — отдельный следующий уровень. Перечень не означает столько же отдельных страниц: несколько функций могут находиться на одном экране.

| Экран / состояние | Пользователь | Функции | Приоритет |
|---|---|---|---|
| Доступ / вход | Все разрешённые пользователи | Защищённый вход до любого удалённого/чужого доступа; понятная ошибка доступа | L1 локально — один владелец без публичной регистрации; сетевой режим требует отдельного gate |
| Старт и библиотека | Ученик | Начать, выбрать открытый профиль, продолжить текущую сессию | Обязательный L1 |
| Карточка и инструктаж | Ученик | Роль, цель, публичная ситуация, язык, длительность, AI-обозначение | Обязательный L1; может быть частью старта |
| Разговор | Ученик | История сообщений текущей сессии, ввод, отправка, завершение | Обязательный L1 |
| Ожидание/ошибка/повтор | Ученик | Сохранение ввода, ясный статус, безопасное восстановление | Обязательные состояния разговора |
| Завершение | Ученик | Предупреждение об открытии скрытых сведений, фиксация сессии, статус подготовки разбора | Обязательное состояние |
| Разбор | Ученик | Факты с доказательствами, частичное раскрытие, отдельные AI-советы, немецкие фразы, повтор | Обязательный L1 |
| Помощь и мои данные | Ученик | Как использовать продукт, языки, хранение/удаление, ограничение AI-советов, связь по проблеме | Минимальная версия обязательна L1 |
| История | Ученик | Собственные прошлые попытки, открыть/удалить, фильтр по карточке | Желательный L1, основной L2 |
| Личный прогресс | Ученик | Тенденции только по сопоставимым попыткам и объяснение ограничений | Желательный L2 |
| Список карточек автора | Автор | Черновики, версии, создать/скопировать, отправить на проверку/утвердить | Обязательный L1 |
| Редактор | Автор | Публичная и закрытая часть, условия, характер, проверка непротиворечивости | Обязательный L1 |
| Preview / журнал | Автор | Синтетическая тренировка и события раскрытия, выявленные проблемы | Обязательный L1 |
| Предоставление результата | Ученик / наставник | Выбор конкретного результата и срока, ограниченный просмотр, отзыв доступа | Перспективный L3 |
| Кабинет наставника / группа | Наставник | Назначенные материалы и добровольно предоставленные результаты, комментарий | Перспективный L3 |
| Служебное управление | Администратор | Доступ, квоты, состояние, ошибки без обычного просмотра текстов | Операции нужны L1; отдельный полный экран желателен позже |
| Лицензии / оплата | Владелец платного аккаунта | Тариф, квота, документы оплаты | Перспективный L3 |
| Голос / генератор / Angebot | По отдельной функции | Самостоятельные новые пользовательские пути | Перспективный L4 |

Предлагаемая технология интерфейса: Jinja2 и небольшой JavaScript в том же FastAPI-приложении. Это поддерживает перечисленные пути без самостоятельного frontend-сервиса. Выбор не утверждает визуальный стиль, расположение блоков или окончательную функциональность Dashboard. Стек описан в [SYSTEM_ARCHITECTURE](SYSTEM_ARCHITECTURE.md).

## 6. Какие показатели допустимы

В L1 приоритет — конкретный завершённый разбор. Если будущий Dashboard показывает числовой показатель, у него должны быть понятные источник, знаменатель и ограничение.

| Показатель | Условие допустимости |
|---|---|
| Полностью выясненные потребности в завершённой сессии | Считаются по действительно озвученным обязательным частям, а не только по `allowed_after`; неизвестность выделена отдельно |
| Количество собственных завершённых тренировок | Не включает preview и технически не завершённые попытки как достижения |
| Изменение результата при повторе | Показаны сценарий/версия и факт знакомства с секретами; не называется доказанным ростом продаж |
| Личная тенденция по навыку | Сравнимые критерии и достаточное количество подходящих попыток; нет смешивания помощи, preview и разных правил |
| Давление, раннее предложение, регистр, следующий шаг | Источник и статус интерпретации видимы; нет иллюзии, что непроверенная AI-классификация является точной мерой |

Не предлагаются единый «рейтинг продавца», прогноз личной пригодности, таблица лучших сотрудников или автоматические решения о допуске/работе. Учебные центры не получают институциональную оценку учащихся как автоматический побочный эффект расширенного Dashboard.

## 7. Простота для A2–B2 и честные ошибки

Предложение L1: короткие подписи, одна основная задача на экран, явный текущий шаг, понятные кнопки, видимый клавиатурный фокус, читаемые сообщения на телефоне и текстовые сообщения об ошибках. Немецкий разговор и DE/RU-разбор разделены; немецкие фразы для практики остаются немецкими.

Живые подсказки по темам скрытых фактов в базовом режиме не нужны: они меняют задачу самостоятельного выяснения. Помощь объясняет интерфейс. Будущую тренировку с подсказками следует обозначать отдельно.

Сбой API не отображается как провал консультации. Если недоступны только AI-советы, можно показать достоверную фактическую часть с пояснением. Если данные недостаточны, показать «не удалось оценить», а не ноль. Подробные состояния восстановления — в [USER_ROLES_AND_FLOWS](USER_ROLES_AND_FLOWS.md), раздел 4.

## 8. Решения владельца

Сначала целесообразно обсудить один пакет: **минимальный Dashboard + отдельное авторское рабочее место + три карточки + текущий разбор без обязательной аналитики истории**. Остальные вопросы уточняют его и не являются приглашением расширить всё сразу.

| Решение | Рекомендация | Что меняется при другом выборе |
|---|---|---|
| Вариант Dashboard для WBS | Минимальный | Стандартный добавляет историю и сравнимость, расширенный — существенный дополнительный scope |
| Минимум карточек и редактор | 3 утверждённых клиента, простой редактор | 1 клиент или отсутствие редактора требуют явного изменения исходного MVP |
| Кто видит личный результат | Ученик; автор L1 — только свои preview | Наставничество требует отдельного предоставления доступа и правил данных |
| Значение «до 15 реплик» | До 15 успешных ходов ученика с ответами; ошибки/повторы доставки не считаются | Иная единица меняет длительность, лимит запросов и дизайн завершения |
| Языки L1 | Немецкий диалог, DE/RU-разбор | Другие языки требуют дополнительной проверки текста и советов |
| История в L1 | После принятия ядра, если остаётся время | Обязательная история увеличивает объём интерфейса, запросов и удаления данных |
| Видимость скрытых потребностей | Только после завершения; нет живых подсказок | Помощь во время тренировки меняет условия попытки и будущие сравнения |
| Сценарий Herr Krüger | Историческая карточка неизменна; расширения только новой версией | Добавление «вчера», маленькой печи или намёка «снова» меняет факты/сложность и требует новых проверок |
| Режим эксплуатации | Закрытый личный MVP как исходное предложение | Внешние пилотные пользователи требуют подтверждения доступа, privacy и эксплуатационных границ |
| Календарь | Подтвердить реальную дату защиты и доступность владельца для приёмки | Без этого восемь дней — относительный рабочий план, не обещание календарной готовности |

Полный реестр решений: [OPEN_DECISIONS](OPEN_DECISIONS.md). Решения о хранении и провайдерах не подменяются выбором вида Dashboard.

## 9. Критерий завершения этапа согласования

Dashboard можно считать согласованным, когда владелец явно выбрал вариант, принял обязательные функции и ограничения видимости, подтвердил исходный MVP либо отдельно записал его сокращение. Согласование фиксируется новым решением с датой; оно не следует автоматически из отсутствия возражений.

На текущем этапе согласование **не получено**. Готовы варианты для обсуждения. Реализация экранов, подключение сервисов и новые платные AI-тесты в A01 не начинаются.
