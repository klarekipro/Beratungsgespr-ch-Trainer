# Первый запуск Consultation Studio

2026-11-05. Версия 0.2 с разговорной ролью клиента, два рабочих места одного владельца. Реальный учебный эффект, естественность беседы и надёжность OpenAI ещё требуют отдельной проверки.

## 1. Открыть приложение

Из корня проекта, Python 3.11+:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dashboard.txt
python scripts/serve_dashboard.py
```

Адрес: http://127.0.0.1:8000. Для другого свободного порта: `--port 8100`. Остановить сервер: Ctrl+C. Данные остаются в локальной SQLite-базе; новая версия сценария не меняет уже начатую беседу.

## 2. Наставник готовит ситуацию

Откройте рабочее место наставника. В карточке компании задайте описание, перечень услуг, условия, ограничения и при необходимости ссылку на источник. Текст с сайта вставляется вручную. Он не превращается автоматически в подтверждённые обязательства компании: наставник проверяет сведения и отмечает карточку как проверенную.

Услуга имеет стабильный ID. Если она используется сценарием, перед удалением нужно изменить этот сценарий. Состояния знания клиента задаются отдельно от значения: «знает», «ещё не решил», «не знает», «не раскрывает», «не относится». Отсутствие обязательного описания отклоняется при сохранении. `no_fit` — допустимый исход без сделки, не отдельная услуга.

В сценарии заполните открытую вводную и скрытые факты двух этапов. Не выдавайте закрытый ответ в названии или первой реплике. Отметьте допустимые итоговые действия. Ключевые слова нужны только технической проверке; OpenAI распознаёт вопросы по смыслу, когда подключён. Примеры вопросов помогают автору проверить карточку и не являются доказательством качества модели.

Для каждого факта различаются «Обязательно выяснить» и «Влияет на итоговое решение». Обязательный факт всегда существенен. Справочную деталь можно сделать необязательной и несущественной: её отсутствие в резюме не мешает переходу. Новое существенное ограничение, даже необязательное, потребует актуализировать ранее подтверждённое понимание. Все произнесённые утверждения резюме проверяются на соответствие фактам.

Заранее задайте реалии, о которых сотрудник может разумно спросить: симптомы, тип, идентификацию оборудования, известность причины неисправности. Если клиент не знает, так и укажите. Отсутствие поля автора само по себе не означает незнания клиента; версия 0.2 показывает в таком случае ограничение сценария вне речи персонажа.

## 3. Ученик проходит беседу

Выберите клиента и режим. При настроенном серверном ключе новая беседа по умолчанию использует OpenAI. Сначала задавайте вопросы о ситуации, причинах обращения и желаемом результате. Кратко сформулируйте потребность и отправьте резюме на проверку. Затем выясните возможности/ограничения и сформулируйте второе резюме. Итоговое предложение допускается после подтверждения обоих этапов.

«Техническая проверка» — ограниченный распознаватель с готовыми фразами, без AI-вызовов. Для полного технического прогона используйте точные примеры из `scenarios/dashboard_demo_walkthrough.json`. Это подсказанный пример, не оценка навыка свободного разговора. Для свободных формулировок выбирайте OpenAI. Текущая техническая попытка не меняет режим после подключения ключа: отдельная кнопка «Новая беседа с OpenAI» создаёт новый разговор.

Можно завершить попытку раньше: разбор честно отметит незавершённые этапы. История позволяет продолжить активную попытку или начать новую. После завершения доступны PDF, TXT и JSON с расшифровкой, версиями карточек, сведениями об этапах и ограничениями оценки.

Кнопка передачи наставнику создаёт запись в очереди внутри приложения. Наставник открывает беседу, читает разбор и оставляет отзыв; ученик видит его в своём результате. Email, Telegram и внешняя отправка не подключены.

## 4. Подключить свой OpenAI API

Остановите сервер и запустите `python scripts/serve_dashboard.py --openai`. Введите ключ в скрытом запросе терминала. Нельзя передавать ключ в чат, исходники, URL или браузер. У приложения нет поля, которое сохраняет ключ в LocalStorage.

Альтернатива — передать `OPENAI_API_KEY` через менеджер секретов окружения процесса. `.env.example` — справочник параметров; приложение не выполняет и не загружает `.env` автоматически. Настроить модель можно через `OPENAI_MODEL` или `--model`. Значение по умолчанию сохраняет модель исторического проекта: `gpt-4.1-mini-2025-04-14`; это не утверждение, что она новейшая или доступна конкретному аккаунту.

После перезапуска статус покажет наличие конфигурации, а выбор OpenAI станет доступен. Этот статус **не означает, что ключ/модель уже проверены платным запросом**. Первый настоящий диалог проверяет доступ. Один успешный ход использует три последовательных запроса к Responses API: распознавание, реплика клиента, отдельная проверка. При ошибке процесс может остановиться после одного или двух запросов. По умолчанию до 30 ходов и 30 AI-попыток на беседу, то есть до 90 обращений при полном использовании; фактическое число попыток API записывается, но это не расчёт стоимости. Автоматических повторов нет. При ошибке ход не засчитывается и не заменяется техническим ответом.

Распознавание намерений, тем и резюме выполняется моделью; программа управляет состоянием. Отдельная роль клиента формулирует естественную реплику на основании только разрешённых фактов. Следующий запрос проверяет содержание, сохранение неопределённостей и клиентскую роль. Только после этого сохраняются ответ и переходы. Structured Outputs и проверяющая модель не гарантируют смысловую правильность. Нужен отдельный живой прогон владельца и разбор ошибок.

Над разговором и в экспорте видны режим и учёт обращений. Старые сессии без счётчика отмечаются как неполный учёт с момента обновления; прежние готовые ответы не переименовываются в новые AI-реплики.

Официальная документация: [Responses/text](https://developers.openai.com/api/docs/guides/text), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

### Обновить установленную версию 0.1

Остановите сервер. Если это Git checkout, обновите ветку `feat/consultation-dashboard` обычным `git pull --ff-only`, сохранив свои изменения. Если это распакованный ZIP, распакуйте обновление в отдельную папку. Из новой папки можно запустить `python scripts/serve_dashboard.py --openai --data-dir /абсолютный/путь/к/старому/проекту/runtime/dashboard`, чтобы использовать прежнюю базу. При пробелах в пути заключите весь путь в кавычки. Не удаляйте старую папку до проверки данных.

Код не переносит ключи и не меняет их настройки. Неизменённые встроенные карточки автоматически получают новую ревизию с явно заданными техническими сведениями. Карточки, отредактированные наставником, и удалённые карточки сохраняют состояние. Старые беседы всегда используют прежний снимок: для проверки исправления начните новую беседу.

Для первого живого прогона используйте «Поиск нового сервисного мастера» и вопросы своими словами: «Что вы имеете в виду?», «Какой номер и мощность и что произошло?», «Причину поломки». Проверьте, что клиент поддерживает контекст, не объявляет учебные этапы, сохраняет свои факты и явно заданные неизвестности. Если возникает ограничение карточки, оно не должно выглядеть как реплика клиента. Затем проверьте резюме и раннее предложение. Сохраните PDF/JSON для содержательного разбора.

## 5. PostgreSQL и внешний запуск

Текущая SQLite-база выбрана для работающего первого запуска без дополнительных серверов. Данные и снимки сценариев отделены от движка через repository. Следующий этап заменяет этот слой PostgreSQL-адаптером с миграциями и переносом данных; одного добавления DATABASE_URL пока недостаточно.

Два интерфейса сейчас доступны одному локальному владельцу. Для нескольких учеников и наставников требуются реальные аккаунты, проверка принадлежности сессии, выдача доступа к разбору и HTTPS. Заголовок X-Workspace-Role отделяет UI-вызовы, но не является аутентификацией. Не открывайте текущий сервер в интернет как готовую многопользовательскую систему.

## 6. Что считается проверенным

Офлайн-тесты проверяют реализацию API, сохранение, последовательность состояний, утверждённые сценарные ответы, экспорт и очередь разбора. Тестовые подстановки проверяют обработку сбоев. Они не измеряют реальный OpenAI и не доказывают, что каждый ученик освоил консультацию. Результаты конкретного запуска записываются в отчёте реализации, отдельно от исторических 74/74.
