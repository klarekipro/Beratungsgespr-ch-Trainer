# Локализация Dashboard (A12)

UI-локаль `de/en/ru` не является языком тренировки. Язык клиента задаётся в библиотечном сценарии и фиксируется в снимке при старте. Переключатель UI меняет только представление и строку `user_preferences.locale` своего пользователя. Simple Actor, профиль, факты, сообщения и оценка не получают UI-локаль.

Словари: `frontend/locales/de.json`, `en.json`, `ru.json`. Загрузчик: `frontend/i18n.js`. Использование: `TrainerI18n.t('auth.login.title')` или `TrainerI18n.t('scenario.case_number', {number:'01'})`. Ключи `dashboard.text_NNN`, `mentor.text_NNN`, `voice.text_NNN`, `auth.text_NNN` — стабильные идентификаторы извлечённых строк A11, не индексы для повторной генерации. Новые строки получают именованные смысловые ключи; существующие ключи не перенумеровывать. Все три словаря должны иметь одинаковые ключи.

Fallback: выбранный язык → немецкий → русский → понятная общая фраза на языке UI. Технический ключ пользователю не показывается. Отсутствующий ключ диагностируется в консоли без пользовательских данных. Для неизвестного кода ошибки показывается локализованное общее уведомление; сырой ответ провайдера не выводится. Backend использует те же словари для безопасных HTTP-ошибок (настройка пользователя; до входа `X-UI-Locale`, по умолчанию de).

Отдельные системные поля отчёта переводятся при отображении через `systemText`. Это не перевод DOM и не поиск/замена в пользовательском содержимом. Неизвестное старое системное наблюдение получает общий текст о ручном разборе; исходный текст остаётся в сохранённом отчёте/локальном экспорте. Сообщения, отзывы, имена, названия, факты и инструкции персонажей не проходят через `systemText`. Сырые диагностические коды и JSON остаются исходными техническими данными.

Даты и время форматируются `Intl.DateTimeFormat`, числа — `Intl.NumberFormat`, множественное число — `Intl.PluralRules`. В русской локали используются формы one/few/other; в немецкой и английской one/other. Для новых числовых сообщений используйте параметры, а не склейку переводимых слов.

До входа только предпочтение UI хранится в `localStorage` под `trainer.ui.locale`, без токенов и паролей. При успешном входе явно выбранная на этой странице локаль сохраняется на сервере. Если выбора не было, восстанавливается локаль пользователя из SQLite (de при отсутствии записи). После входа PUT `/api/auth/preferences` защищён авторизацией, CSRF и проверкой Origin; ID пользователя берётся из серверной сессии. Настройка доступна и до обязательной смены временного пароля, но не открывает остальные защищённые API.

Для обновления всех подписей UI перезагружается после изменения языка. При несохранённом вводе запрашивается подтверждение; сначала сохраните форму или отправьте реплику. Сохранённые разговоры не меняются. PDF/JSON/TXT сохраняют подлинные реплики; существующий PDF-экспорт использует прежние русские системные заголовки. Их локализация не выполнялась в A12.

Миграция: добавлена отдельная таблица `user_preferences`, старые users/auth_sessions/documents не изменяются. A11 игнорирует дополнительную таблицу, поэтому откат не требует удаления данных. Восстановление пароля не сбрасывает локаль.

При проверке перевода не принимайте авторский русский текст сценария на немецкой странице за непереведённый UI: автоматический перевод таких данных запрещён. Физическая диктовка, Safari и интеграция конкретного менеджера паролей проверяются владельцем отдельно.
