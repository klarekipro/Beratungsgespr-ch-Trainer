# A13: решительный клиент и разбор беседы

## Профиль

`profiles/personas/decisive.v2.json` — новая техническая версия решительного характера, ожидающая содержательной приёмки владельцем. Она заменяет аналитическую манеру v1 практической: учитывать уже полученные ответы, обычно задавать один существенный вопрос, допускать рост доверия и условный следующий шаг. Не вводится запрет на составные вопросы.

При первом запуске обновляется только неизменённый исходный `decisive_oven v1`. Прежняя версия сохраняется в `client_profile_version`; снимки разговоров не меняются. Если владелец уже сохранил собственную редакцию профиля, автоматическая миграция её пропускает. Шаблон v2 можно применить через существующий Persona Studio вручную. Повторный запуск миграции не создаёт новых версий. Нерешительный характер и сценарные факты не меняются.

Архитектура Simple Actor прежняя: один Responses-вызов, локальные критические проверки, без обязательного LLM-Verifier. Общая инструкция уточняет различие условного интереса и обязывающего заказа; запрет реального обязательства сохраняется. Добавлен прямой запрет придумывать адреса и обещать отправку материалов без основания. Это инструкция модели, а не строгая семантическая гарантия.

## Оценка

Наставник: «Результаты» или «Сотрудники → история» → завершённая беседа. Полная расшифровка раскрывается на этом же экране.

Для Simple Actor у каждого этапа отдельная отметка:

- не проверено наставником;
- выполнено;
- частично выполнено;
- не выполнено.

Результат разговора выбирается отдельно: без следующего шага, интерес, предварительная диагностика, подтверждённый визит, ремонт после необходимых условий, услуга недоступна, отказ клиента. Пустое значение означает, что наставник ещё не определил исход. Есть отдельная отметка соответствия услугам компании. Сохранённая карточка компании показана рядом с разбором. В комментарии указываются основания и номера ходов.

Не блокируется запись фактически достигнутого, но неподдерживаемого обещания: наставник должен иметь возможность отразить нарушение, а не потерять свидетельство. Этот исход не присваивает учебных баллов. Само согласие клиента не подтверждает ни один этап.

Существующий Mentor Review сохраняет `mentor_assessment`, автора, дату и комментарий в документе беседы. Новые оценки не изменяют разговорное `state`, сообщения или снимки. Старый API с булевыми отметками остаётся совместимым; смешение двух контрактов отклоняется. Для старых оценок явно подтверждённые этапы читаются как выполненные; неотмеченные не превращаются задним числом в провал. Старый service outcome не преобразуется автоматически в коммерческое согласие.

До оценки экран и экспорт сообщают: «Беседа завершена. Ожидается оценка наставника». При частичной проверке видны отдельные оставшиеся непроверенные этапы. PDF/TXT/JSON показывают те же сохранённые отметки, коммерческий исход, соответствие компании и комментарий. Авторские реплики остаются исходными. DE/EN/RU интерфейс сохраняется; PDF, как в A12, использует русские системные подписи.

Исторические сохранённые отчёты не переписываются при чтении: для Simple Actor используется актуальное представление. Старый скачанный PDF сам не изменяется; для исправленного отображения его надо скачать заново.

## Ограничения

Оценка содержания и соответствия компании выполняется человеком. Новая версия характера требует ручной приёмки. Общая полнота фактов, адреса и естественность не гарантируются локальными проверками. API-ключ, авторизация, языковые настройки и диктовка не менялись.
