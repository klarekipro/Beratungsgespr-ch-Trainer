# Единая локальная установка Klare KI

Рабочая папка: `/Users/admin/Documents/01_AI Business 26/17_BeratungGesprech`.
Адрес: **http://127.0.0.1:8100**. Устанавливается A06 и её проверенные последующие
версии. Учебная логика и Actor/Director в A07 не менялись.

## Обычный запуск

В Finder дважды щёлкните `START_TRAINER.command`. Скрипт сам определяет свою
папку, проверяет Python/.venv и версии зависимостей. Установка пакетов выполняется
только при отсутствии требуемых версий. После проверки API/SHA/модулей открывается
браузер. Повторный запуск использует тот же исправный процесс. Конкурирующие
запуски сериализованы файловой блокировкой.

Если 8100 занят чужим процессом, запуск отменяется с PID; чужой процесс не
останавливается. Старый процесс тренажёра определяется по cwd, имени Python-скрипта,
PID порта и времени запуска, повторно проверяется перед SIGTERM. SIGKILL не
используется. `STOP_TRAINER.command` останавливает только этот проект.

## OpenAI и macOS Keychain

При первом запуске в Terminal появляется скрытый запрос. Введите ключ один раз.
Он сохраняется как generic password в macOS Keychain: service
`pro.klareki.beratungstrainer.openai`, account `default`. Ключ привязан к текущему
устройству и доступен при разблокированной Связке ключей. macOS может запросить
разрешение для локального `keychain-helper`; разрешайте доступ только ему.

Keychain helper собран из `scripts/mac_keychain.c` штатным C/Security API
и хранится в `~/Library/Application Support/KlareKITrainer/keychain`.
При отсутствии компилятора установите Apple Command Line Tools.
Ключ не попадает в Git, .command, argv, .env, браузер или логи. Из Keychain он
передаётся Python-серверу через анонимный pipe и устанавливается в окружение уже
внутри нового процесса. Секреты из памяти старых процессов не извлекаются.

`OPENAI_KEY.command` позволяет заменить ключ, удалить его и остановить сервер,
либо проверить наличие без показа значения. Замена перезапускает тренажёр.
При ошибке/блокировке Keychain plaintext-обхода нет: разблокируйте Связку ключей и
повторите. При утрате ключа создайте новый в OpenAI и замените через эту кнопку.

## Проверяемое обновление

`UPDATE_TRAINER.command` использует явно закреплённый `runtime/update-target.json`.
В нём всегда полный SHA; main или произвольный latest автоматически не выбираются.
Если файла нет, скрипт предлагает ввести полный SHA опубликованного GitHub commit.
Доступ к приватному Git — через настроенный credential helper `gh`.

Для опубликованной версии:

```json
{"source":"github","repository":"https://github.com/klarekipro/Beratungsgespr-ch-Trainer.git","commit":"ПОЛНЫЙ_40_СИМВОЛЬНЫЙ_SHA"}
```

A04–A07 пока не публиковались. Для них предусмотрен **явно выбранный локальный
release bundle**, созданный из сохранённой истории данного проекта. Его абсолютный
путь, SHA-256 и целевой commit закрепляются в target-файле. Bundle проходит Git
verify, проверку checksum и принадлежности commit его истории. Это проверка
целостности явно одобренного локального источника, а не утверждение, что commit
уже доступен в GitHub. Не подменяйте bundle файлом неизвестного происхождения.

```json
{"source":"bundle","repository":"https://github.com/klarekipro/Beratungsgespr-ch-Trainer.git","commit":"ПОЛНЫЙ_SHA","path":"/абсолютный/путь/release.bundle","sha256":"SHA256_ФАЙЛА"}
```

Текущая установка должна иметь чистое Git-дерево. Уникальные файлы не удаляются;
при конфликте обновление останавливается. Ключи, runtime и локальные SQLite
игнорируются Git и не мешают обновлению. Версия должна происходить от A06 и иметь
операционные файлы A07, чтобы обновление не убрало кнопку управления.

До остановки работающего сервера в отдельном временном worktree создаётся .venv,
устанавливаются зависимости, выполняются все dashboard unittest и Node syntax check.
Если проверки не прошли, текущий сервер не останавливается. После успешной проверки
сохраняются предыдущий SHA, .venv и согласованный SQLite-снимок в
`~/Library/Application Support/KlareKITrainer/rollback`.

После переключения выполняются запуск и проверка SHA, PID, пути/хешей модулей и
OpenAI configured. При неудаче автоматически восстанавливаются исходники,
окружение и SQLite-снимок; предыдущий сервер запускается снова. Неудачные данные
сохраняются отдельно. Git reset --hard и git clean не используются.

Ручной откат последнего обновления:

```sh
./UPDATE_TRAINER.command --rollback
```

Ручной откат сохраняет текущую базу разговоров; автоматический откат неуспешного
обновления возвращает согласованный предустановочный SQLite-снимок, сохраняя
неудачную базу отдельно. Совместимость схемы будущих релизов должна проверяться
до их одобрения. Не переключайте HEAD вручную между обновлением и откатом.

## Данные и диагностика

Единственный активный каталог данных — `runtime/`: `dashboard/trainer.sqlite3`,
`logs/`, частный `audit/`, журнал обновления и закреплённая версия.
`/api/status` фиксирует фактически загруженный commit, Python, PID и пути модулей.
Статус A06 `0.3.0-semantic-planning` сам по себе не доказывает качество AI.
Две настоящие консультации проверяются отдельно от успешного запуска.

Не помещайте беседы, audit JSON, PDF или ключи в Git. Git bundle и резервные
исходники A04–A06 сохранены отдельно от активной установки. Старые worktree-копии
после проверки переносятся в Корзину, отчёты A04/A05/A06 сохраняются.
