# A10 — кабинеты, персонажи и диктовка

Одна установка, один запуск START_TRAINER.command, один адрес 127.0.0.1:8100.
Это расширение A09, не новое приложение. Новые тренировки используют Simple Actor.

## Первый наставник

В рабочей папке откройте **SETUP_MENTOR.command** двойным щелчком. Укажите собственный
уникальный логин латиницей, имя и пароль от 12 до 128 символов. Пароль вводится
скрыто, дважды, не передаётся аргументом команды и не выводится в журнал.
Универсального логина/пароля нет. Повторная первоначальная настройка запрещена,
пока существует активный mentor_admin. Создать наставника через открытый API нельзя.
Локальный владелец с доступом к файлам Mac может выполнить эту процедуру — это
граница доверия локальной установки. Не давайте сотрудникам доступ к macOS-профилю
владельца, SQLite и Keychain: веб-авторизация не защищает от владельца файлов ОС.

Вход наставника: **http://127.0.0.1:8100/mentor**.
Вход сотрудника: **http://127.0.0.1:8100/learner**.
Есть общая страница /login с выбором кабинета; роль определяется сервером, а не
переключателем или заголовком запроса. Переключателя ролей после входа нет.

## Сотрудники и история

В Mentor Portal → «Сотрудники» создайте логин, имя и временный пароль. Передайте
пароль лично или другим согласованным безопасным способом. При первом входе
сотрудник обязан сменить его; до этого доступ к тренировкам закрыт. В верхнем меню
каждый может изменить собственный пароль. Наставник может сбросить временный
пароль или деактивировать сотрудника. Текущий пароль наставнику недоступен.
Сброс и деактивация отзывают все сессии сотрудника. Удаления с потерей истории нет.

Нажмите имя сотрудника, чтобы открыть его активные и завершённые беседы. Наставник
может читать и экспортировать их. В «Проверке бесед» доступны все результаты,
очередь и отдельные записи «Архив A09 без владельца». Старые данные не назначаются
случайному сотруднику. Архивные активные беседы доступны наставнику только для
чтения/экспорта, а не для продолжения под чужим именем.

Сотрудник видит только свои беседы и собственный отзыв. Включая прямой запрос к
API или URL экспорта: чужой ID возвращает 404. Закрытый сценарный снимок, характер,
условия раскрытия, raw audit и правила оценки не отдаются сотруднику даже после
завершения. Его PDF/TXT/JSON содержат разрешённый результат и фактический разговор.
Полный разбор и закрытое досье доступны наставнику.

Для проверки двух учётных записей используйте два отдельных профиля браузера
или обычное и приватное окно. Две вкладки одного профиля используют одну cookie
и не представляют двух независимых пользователей.

## Persona Studio

Mentor Portal → «Конструктор клиентов». Основные подготовленные образы:
**Решительный** и **Нерешительный**. Дополнительные пять черновиков A09 сохранены,
но по умолчанию не предлагаются сотрудникам. Пользовательские профили и уже
созданные SQLite-версии не перезаписываются при последующем запуске.

Редактируйте поля характера, речи, принятия решений, отношения к продавцу,
давлению, повторным вопросам и сомнениям. Дополнительные поведенческие указания
задают стиль; не заменяют системные правила и не являются источником фактов.
Факты, неизвестные сведения, условия раскрытия и допустимые исходы редактируются
отдельно в том же визуальном конструкторе. Можно взять основу из существующей
библиотеки сценариев, затем адаптировать досье данного профиля.

«Доступен сотрудникам» управляет выбором в новой тренировке. Скрытие профиля не
мешает продолжить уже начатую беседу с её прежним снимком. «Сохранить новую версию»
создаёт SQLite-ревизию; версии изменённых блоков обновляются отдельно. Активные
беседы не меняются. «Дублировать» создаёт новый ID; «Предпросмотр» показывает
собранное досье без системного промпта. Экспорт JSON выгружает сохранённую версию;
импорт проходит серверную валидацию и сначала открывается как черновик.

Сценарий имеет собственную версию и снимок исходной карточки. При редактировании
фактов обновляется ревизия снимка; исходная библиотечная карточка не переписывается
молча. Для изменения общей основы используйте прежний раздел «Сценарии», а затем
явно примените её в нужном профиле. Несколько клиентов могут использовать одну
основу. Факты первоначального промышленного случая A09 не изменены.

`author_missing` — автор не предоставил данные; `customer_unknown` — автор явно
задал незнание клиента. В прежних фактах этому соответствует `does_not_know`.
Не вводите фиктивные параметры, чтобы заставить модель отвечать увереннее.
Условия after_needs/after_capabilities по-прежнему не открываются автоматически
в живом Simple Actor: подтверждение этапов выполняется наставником после беседы.
Для разрешённых на протяжении разговора сведений используйте available.

## Разговор и ручной разбор

В Employee Portal нет выбора «Вопрос / Резюме / Предложение». Сотрудник пишет
обычный текст или диктует, затем нажимает отправку. Один Actor получает разрешённое
досье и историю. Он не видит закрытую карточку фирмы и rubric. Слова продавца и
предыдущие сообщения модели не становятся утверждёнными фактами.

После завершения наставник открывает результат и оставляет отзыв. Флажок ручной
оценки позволяет подтвердить потребности → возможности → обоснованный итог только
в этом порядке. Это оценка наставника после просмотра, не автоматическая AI-оценка.
Технические отказы не засчитываются ошибкой ученика. Нельзя считать раннее согласие
модели успешной учебной сделкой; статусом управляет Python/наставник.

## Микрофон

Рядом с полем сообщения нажмите «Микрофон», разрешите доступ браузеру, выберите
русский или немецкий. Нажмите «Остановить»; запись также автоматически ограничена
примерно минутой. Текст добавляется в поле, его можно исправить. Только отдельное
нажатие «Отправить» обращается к клиентскому Actor. «Отменить запись» освобождает
микрофон и прекращает ожидание; уже отправленный API-запрос может быть учтён.
При ошибке существующий текст не очищается. При переходе со страницы микрофон
освобождается. Во время записи/распознавания отправка сообщения приостановлена.

Chrome обычно записывает WebM/Opus, Safari — MP4/AAC; формат выбирается через
MediaRecorder.isTypeSupported. На сервере проверяются сигнатура, аудиодорожка,
размер до 4 МБ и длительность до 60 секунд через ffprobe. ffprobe должен быть
доступен в PATH, /opt/homebrew/bin или /usr/local/bin. В этой macOS-установке он
найден. Неизвестные/пустые/длинные записи отклоняются до вызова OpenAI.
Сырое аудио не сохраняется постоянно; временная копия для проверки удаляется.

Транскрибация использует существующий Keychain-ключ и поддерживаемую модель
`gpt-transcribe`, доступность которой проверяется в локальной конфигурации.
OPENAI_TRANSCRIPTION_MODEL может явно выбрать другую совместимую модель;
автоматического скрытого переключения нет. Учитываются отдельные попытки API
диктовки; они не притворяются ходами консультации. Доступ к микрофону требует
действия пользователя. Физическую запись и Safari нужно проверить владельцу.

## Безопасность и эксплуатация

Argon2id хранится в users; случайная auth-cookie — HttpOnly, SameSite=Strict,
8 часов. В SQLite хранится только SHA-256 случайного session token. CSRF-токен
хранится в памяти страницы, не localStorage; мутации требуют его и точный Origin.
Смена пароля ротирует сессию, сброс/выход/деактивация её отзывают. Вход ограничен
по сочетанию логин/IP и по IP; сообщение не раскрывает неверный реквизит.

На localhost cookie без Secure, поскольку HTTPS отсутствует. Для будущего удалённого
использования обязательны HTTPS, корректно доверенный reverse proxy и
TRAINER_REMOTE_HTTPS=1; HTTP в этом режиме запрещён, cookie получает Secure.
VPS/облако в A10 не настраивались. До внешнего развёртывания нужен отдельный review
прокси, TLS, ресурсов и политики данных. Результат A10 не является сертификацией
безопасности или признанием коммерческой готовности.

Полный /api/status доступен наставнику и локальному контроллеру по отдельному
файловому installation-token (0600); браузер сотрудника этот токен не получает.
«Подключение AI» показывает параметры, «Техническая диагностика» в разборе — только
коды и безопасные категории. Ключи, промпты и необработанные upstream-ответы не
включаются. Полные исходные аудиты остаются только в локальном runtime/audit.

Установка обновляется прежним механизмом закреплённого commit/bundle, с резервной
копией. После создания аккаунтов контроллер запрещает случайный откат к A09 или
другой версии без авторизации: такой запуск раскрыл бы новые данные. Исходники
и предмиграционная SQLite сохранены; восстановление старой версии выполняется
только отдельно и офлайн, с осознанным выбором соответствующей резервной базы.
Совместимый защищённый commit можно обновлять/восстанавливать штатно.

Проверка релиза A10: scripts/release_smoke.py — несколько функциональных потоков
с обязательными отрицательными проверками прав, миграции и экспорта, плюс синтаксис
JavaScript. Старые тесты tests/dashboard сохранены как историческая регрессия;
анонимные HTTP-fixtures A09 намеренно несовместимы с обязательной авторизацией.
Обход авторизации ради их старых ожиданий не добавлен. Количество тестов не
используется как доказательство содержательного качества клиента.

Официальные источники реализации: [OpenAI File transcription](https://developers.openai.com/api/docs/guides/speech-to-text),
[Argon2-cffi](https://argon2-cffi.readthedocs.io/en/stable/howto.html),
[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
