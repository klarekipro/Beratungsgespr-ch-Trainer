# A19.1 — вход в кабинет другой роли

10.11.2026. Основание `6d5b0c5`, отдельная ветка `codex/a19-1-portal-entry`. Версия `0.11.1-portal-entry`.

Владелец получил JSON `FORBIDDEN` при открытии `/mentor` в Chrome и Safari. В исходном маршруте это происходило при активной сессии сотрудника: вместо страницы входа возвращался API-подобный 403; Safari дополнительно неверно отображал кодировку тела ошибки.

Теперь только HTML-маршруты `/mentor` и `/learner` при несовпадении роли направляют на `/login?portal=…&reason=role`. На форме выбран нужный кабинет, показано пояснение DE/EN/RU и ссылка «Открыть свой кабинет». Существующая сессия остаётся действующей; роль меняется только после успешного обычного входа в другой аккаунт. API по-прежнему отвечает 403 при отсутствии нужных прав. Аккаунты, пароли, сессии владельца и рабочие беседы вручную не изменялись.

Дополнительно устранено переполнение языкового списка формы входа на 390 px, пустая полоса ошибки скрыта. Оформление принятого кабинета сотрудника не менялось.

Проверка:

- Один целевой `PortalSmoke.test_wrong_portal_opens_login_without_changing_role_or_session`: обе роли, оба HTML-маршрута, анонимный вход, UTF-8 HTML/no-store, сохранённая сессия, прежний 403 API, отказ входу с неподходящей ролью — OK. Временная тестовая SQLite; без платных вызовов.
- Chromium на обезличенной копии 8101: реальный переход сотрудник → `/mentor` → форма наставника, DE/EN/RU, 1440×900 и 390×844 без переполнения; ссылка открывает текущий кабинет с клавиатуры; API наставника остаётся 403. Два JPEG без EXIF — `reports/a19-1/screenshots/`.
- JS syntax, JSON локалей, `git diff --check` — OK. Сохраняется прежнее предупреждение Starlette/httpx.
- Safari отдельно в этой проверке не управлялся. Исправлен общий серверный путь обоих браузеров; повторный просмотр владельцем остаётся желателен.
