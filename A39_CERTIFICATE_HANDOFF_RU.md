## Полное имя — дополнение A34

Обязательное поле «Полное имя получателя сертификата (имя и фамилия)» пустое при новой выдаче. Нет подстановки login/display_name. Наставник вручную вводит нужное написание и редактирует через «Изменить данные». Для совместимости payload использует прежнее поле `print_name`; при создании нового preview дополнительно сохраняется независимый `recipient_full_name`. PDF использует именно этот снимок. На final issue требуется не менее двух непустых частей имени (не проверка юридической личности). Старые записи не дополняются и не получают вымышленных фамилий. Старый draft без полного имени напрямую не выдаётся: нужен новый preview с введённым именем. Уже issued возвращается по прежней идемпотентной ветке без нового требования/перезаписи.

Выдача не следует из AI, количества попыток, reviewed/pass/коммерческого исхода. Прежние ограничения выбранного контекста/собственных завершённых и доступных mentor бесед сохранены. Основание может включать несколько попыток; наставник самостоятельно подтверждает общую компетенцию. Никаких процентов, автоматической выдачи или нового Actor/провайдера.

## История и неизменность

Только новые preview получают design_version/language/recipient_full_name. Старые сертификаты без design_version экспортируются прежним кодом; миграции/backfill нет. При явной выдаче новый PDF фиксируется побайтно в `pdf_snapshots.issued` той же certificate-записи. GET возвращает эти байты, независимо от query language/изменений аккаунта/будущей вёрстки. Снимки не включаются в JSON API/списки. Прежние явные revoke/replace сохраняют issued-снимок и отдельно фиксируют PDF соответствующего статуса с маркировкой. Исторические беседы, снимки материалов, оценки и опубликованные отзывы не переписываются.

## A34 Addendum 2 — редактируемое полное имя выдающего

Продолжение той же ветки `codex/a39-certificate-design`, без нового проекта/ветки. До изменения проверены HEAD `6169e0b023b5e3997cb15e5af85cbc7ef5842e8c`, чистые tracked-файлы и8100 PID35718. Новый шаблон только для новых preview: `a39-v2`, backend0.15.1-certificate-issuer.

В форме два независимых редактируемых поля: полное имя получателя и «Имя и фамилия выдающего сертификат» / `Name des Ausstellers` / `Issuer Full Name`. Профиль сейчас содержит только username/display_name, без достоверного отдельного ФИО, поэтому при новой выдаче оба поля пустые. Login/Sergii не подставляется и не считается полным именем. При явной замене сертификата тем же наставником можно исправить его прежде вручную введённый issuer_full_name; имя другого наставника автоматически не переносится.

Новый payload/record хранит `issuer_full_name` отдельно от `mentor_id` и прежнего служебного `mentor_name`. Поле до120 Unicode-символов, required в форме, перед final issue проверяются минимум две непустые части имени. Пустое имя/одиночное Sergii →422 `CERTIFICATE_ISSUER_FULL_NAME_REQUIRED`. Это проверка заполнения, не юридическая проверка личности. PDF-preview и финальный snapshot печатают именно введённое ФИО в разделе MENTOR / AUSSTELLER. Оно также показывается в списке сертификатов. Правка поля не вызывает изменения аккаунта/аутентификации. Повторная выдача с другим именем выдающего не возвращает ошибочно старый сертификат через content idempotency.

История не мигрирует: issuer_full_name не добавляется старым записям; frozen PDF прежних issued возвращается побайтно. Для старых записей без поля в старом шаблоне остаётся прежняя подпись mentor_name, а не выдуманная фамилия. Старый draft без ФИО выдающего нельзя финально выдать напрямую: нужен новый preview с явным вводом. Содержимое ранее выданного сертификата не меняется при смене display_name/настроек наставника.
